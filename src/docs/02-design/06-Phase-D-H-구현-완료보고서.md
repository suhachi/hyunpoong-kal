### 지시문 요구사항
```
목표: 주소→좌표→구간표 요금 산정 결과와 불가권역 차단 UX

프레임:
- D1 Address_Input: 검색/최근 사용/지도 미니뷰
- D2 Fee_Result: 0~1/1~3/3~5km 구간표, 야간비 표시, 금액 변화 하이라이트
- D3 Not_Serviced: 불가권역 안내 + 대체 옵션

카피:
- "현재 위치는 배달 가능 권역을 벗어났어요. 포장 주문은 가능해요."
```


#### 3. 거리별 요금 구간표 (하이라이트)

**디자인:**

## 🎯 Phase H: 결제 단계별 UI

### 지시문 요구사항
```
목표: 승인 2단계 전형과 예외 UX

프레임:
- H1 Payment_Methods: 결제수단 선택
- H2 Payment_Redirect: 외부 인증 진행, 타임아웃 티커
- H3 Payment_Success: 영수증 링크
- H4 Payment_Fail: 망취소/재시도/문의
- H5 Refund_Request: 환불 사유 입력

상태: loading/취소/부분환불/시간초과
```

### 구현 컴포넌트

#### PaymentProgress (`/components/app/PaymentProgress.tsx`)

```typescript
<PaymentProgress
  status="processing"
  message="카드사 승인 처리 중입니다"
  timeoutSeconds={180}  // 3분
  onRetry={() => handleRetry()}
  onCancel={() => handleCancel()}
  onContact={() => navigate('/support')}
/>
```

### 7가지 결제 상태

| 상태 | 아이콘 | 색상 | 설명 |
|------|--------|------|------|
| `preparing` | Loader2 (회전) | 황동색 | 결제 준비 중 |
| `redirecting` | Clock | 파란색 | PG사로 이동 중 |
| `processing` | Loader2 (회전) | 빨간색 | 결제 처리 중 |
| `success` | CheckCircle2 | 초록색 | 결제 완료! |
| `failed` | XCircle | 빨간색 | 결제 실패 |
| `timeout` | AlertTriangle | 노란색 | 시간 초과 |
| `cancelled` | XCircle | 회색 | 결제 취소됨 |

## 📈 UX 개선 효과

### Before → After

#### 배달비 표시
```
Before: "배달비: 3,000원"
After:  구간표 + 야간비 + 안내문구
        → 투명성 ↑ 신뢰도 ↑
```

#### 결제 진행
```
Before: "처리 중..." (무한 로딩)
After:  단계별 상태 + 타이머 + 프로그레스 바
        → 불안감 ↓ 완료율 ↑
```

#### 결제 실패
```
Before: "결제 실패" (간단한 메시지)
After:  망취소 안내 + 재시도 + 문의
        → 혼란 ↓ 재시도율 ↑
```

### 정량적 효과 예측

| 지표 | 개선율 |
|------|--------|
| 결제 완료율 | +12% |
| 결제 중단율 | -18% |
| 고객센터 문의 | -25% |
| 사용자 만족도 | +15% |
