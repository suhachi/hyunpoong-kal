## ✅ 해결 방법

### 1. `getCurrentUser()` 동기 함수로 변경

**lib/auth.ts (수정):**
```typescript
/**
 * 현재 로그인한 사용자 정보 가져오기 (동기)
 */
export function getCurrentUser(): AuthUser | null {
  if (USE_FIREBASE) {
    return null;
  }

  // Mock: localStorage에서 역할 가져오기 (테스트용)
  const mockRole = localStorage.getItem('mockRole') || 'owner'; // ✅ 기본값 owner
  return mockRole === 'owner' || mockRole === 'admin' ? MOCK_ADMIN : MOCK_CUSTOMER;
}

/**
 * 현재 로그인한 사용자 정보 가져오기 (비동기 - 호환성 유지)
 */
export async function getCurrentUserAsync(): Promise<AuthUser | null> {
  return getCurrentUser();
}
```

### 3. requireAdmin 함수 수정

**lib/auth.ts (수정):**
```typescript
/**
 * 관리자 페이지 접근 가드
 * 관리자가 아니면 홈으로 리다이렉트
 */
export async function requireAdmin(): Promise<AuthUser> {
  const user = getCurrentUser(); // ✅ 동기 함수 호출
  
  if (!isAdmin(user)) {
    window.location.href = '/';
    throw new Error('Unauthorized');
  }
  
  return user!;
}
```

## 🔑 핵심 포인트

### 1. Mock 모드 (개발 중)

```
현재 상태:
- USE_FIREBASE = false (lib/auth.ts)
- localStorage에 'mockRole' 저장
- 기본값: 'owner' (관리자 권한)

프로덕션:
- USE_FIREBASE = true
- Firebase Auth 사용
- 실제 사용자 역할로 판단
```

### 2. 역할 체계

```
owner (소유자):
✅ 모든 관리자 기능 접근
✅ 설정 센터 접근
✅ 민감한 설정 변경

admin (관리자):
✅ 대부분의 관리 기능
✅ 설정 센터 접근
⚠️ 일부 민감한 설정 제한 (필요시)

customer (고객):
❌ 관리자 페이지 접근 불가
❌ 설정 센터 접근 불가
✅ 고객 앱만 사용
```

### 3. 접근 제어 흐름

```
사용자 접속
   ↓
App.tsx: ProtectedRoute (owner 필요)
   ↓
AdminLayout: requireAdmin() 체크
   ↓
Settings/index.tsx: role 재확인
   ↓
접근 허용 / 거부
```
