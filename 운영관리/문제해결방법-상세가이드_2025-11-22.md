### 🔴 문제 상황

### ✅ 최선의 해결 방법

**`useAuth()` hook을 사용하여 실제 인증 사용자 정보 가져오기**

#### 이유
1. **중앙 집중식 관리**: `AuthContext`에서 인증 상태를 중앙에서 관리
2. **자동 업데이트**: 로그인/로그아웃 시 자동으로 상태 업데이트
3. **타입 안전성**: TypeScript 타입 체크 지원
4. **일관성**: 모든 페이지에서 동일한 방식으로 사용자 정보 접근

##### Step 1: 공통 HOC 또는 Hook 생성 (선택사항)

```typescript
/**
 * 인증이 필요한 페이지를 위한 커스텀 Hook
 * 로그인하지 않은 경우 자동으로 로그인 페이지로 리다이렉트
 */
import { useEffect } from 'react';
import { useNavigate } from 'react-router-dom';
import { useAuth } from '../contexts/AuthContext';
import { LoadingSkeleton } from '../components/shared/LoadingSkeleton';

export function useRequireAuth() {
  const { user, loading } = useAuth();
  const navigate = useNavigate();

  useEffect(() => {
    if (!loading && !user) {
      navigate('/login', { replace: true });
    }
  }, [user, loading, navigate]);

  if (loading) {
    return { user: null, loading: true, LoadingComponent: LoadingSkeleton };
  }

  if (!user) {
    return { user: null, loading: false, LoadingComponent: null };
  }

  return { user, loading: false, LoadingComponent: null };
}
```

## 3. getCurrentUser() Firebase 모드 구현

### 🔴 문제 상황

`USE_FIREBASE=true`일 때 `getCurrentUser()`가 항상 `null`을 반환

### ✅ 최선의 해결 방법

**`getCurrentUser()`를 제거하고 `useAuth()` hook 사용을 권장하거나, 동기적 제한을 명확히 문서화**

#### 이유
1. **React 패턴**: React에서는 Context/Hook 패턴이 표준
2. **비동기 처리**: Firestore 조회는 비동기이므로 동기 함수로는 불가능
3. **상태 관리**: Context를 통해 자동으로 상태 업데이트

#### 구현 방법

##### 방법 A: getCurrentUser() 제거 및 useAuth() 사용 권장 (권장)

/**
 * @deprecated 이 함수는 Mock 모드에서만 작동합니다.
 * Firebase 모드에서는 useAuth() hook을 사용하세요.

### ✅ 최선의 해결 방법

**옵셔널 체이닝(`?.`)과 기본값 사용**

#### 이유
1. **간결성**: 코드가 간결하고 읽기 쉬움
2. **안전성**: 런타임 에러 방지
3. **타입 안전성**: TypeScript에서 타입 체크 지원

#### 구현 방법

**`src/pages/app/OrderHistory.tsx`**

```typescript
        <ImageWithFallback src={firstItem.menuImage} />

      // ...
```

```typescript
// ✅ 수정 후
function OrderCard({ order, hasReview, formatDate }: OrderCardProps) {
  // ✅ 안전한 배열 접근
  const firstItem = order.items?.[0];
  const totalItems = order.items?.length || 0;

  // ✅ items가 비어있는 경우 처리
  if (!firstItem || totalItems === 0) {
    return (
      <Card className="rounded-2xl border-[#E5DDD5]">
        <CardContent className="p-4 text-center text-gray-500">
          주문 항목이 없습니다
        </CardContent>
      </Card>
    );
  }

  return (
    <Card>
      {firstItem.menuImage && (
        <ImageWithFallback src={firstItem.menuImage} />
      )}
      <p>{firstItem.menuName}</p>
      {totalItems > 1 && (
        <p className="text-sm text-[#2E1C10]/60">
          외 {totalItems - 1}개
        </p>
      )}
      // ...
    </Card>
  );
}
```

## 6. 에러 처리 개선

### 🔴 문제 상황

일부 API 호출에서 에러 처리가 불완전하거나 사용자에게 피드백이 없음

### ✅ 최선의 해결 방법

**toast 알림 추가 + 빈 상태 처리**

#### 이유
1. **사용자 경험**: 에러 발생 시 사용자에게 명확한 피드백
2. **디버깅**: 개발자에게 에러 정보 제공
3. **안정성**: 에러 발생 시에도 앱이 정상 작동

#### 구현 방법

**공통 에러 처리 유틸리티 생성**

**`src/lib/utils/error-handling.ts`** (새 파일)

```typescript
import { toast } from 'sonner';

export interface ErrorHandlerOptions {
  showToast?: boolean;
  toastMessage?: string;
  logError?: boolean;
  fallbackValue?: any;
}

/**
 * API 에러 처리 유틸리티
 */
export async function handleApiError<T>(
  promise: Promise<T>,
  options: ErrorHandlerOptions = {}
): Promise<T | null> {
  const {
    showToast = true,
    toastMessage = '작업을 완료하는데 실패했습니다. 다시 시도해주세요.',
    logError = true,
    fallbackValue = null,
  } = options;

  try {
    return await promise;
  } catch (error) {
    if (logError) {
      console.error('[API Error]', error);
    }

    if (showToast) {
      toast.error(toastMessage);
    }

    return fallbackValue;
  }
}
```

**사용 예시**

```typescript
// ✅ 수정 후
import { handleApiError } from '../../lib/utils/error-handling';
import { toast } from 'sonner';

async function loadOrders() {
  if (!user) return;

  setLoading(true);
  
  const data = await handleApiError(
    getOrdersByUser(userId),
    {
      toastMessage: '주문 내역을 불러오는데 실패했습니다. 다시 시도해주세요.',
      fallbackValue: [],
    }
  );

  if (data) {
    setOrders(data);
  } else {
    setOrders([]); // 빈 배열로 초기화
  }
  
  setLoading(false);
}
```
