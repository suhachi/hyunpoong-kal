# 문제 분석 보고서: 마이페이지 인증 체크 누락

**작성일**: 2025-11-22  
**문제**: 로그아웃 후 마이페이지(`/my`) 접근 시 로그인 페이지로 리다이렉트되지 않음  
**상태**: ✅ 해결 완료

---

## 📋 문제 요약

### 증상
- 사용자가 로그아웃 후에도 마이페이지(`/my`)에 접근 가능
- 로그아웃 후 마이페이지를 터치하면 로그인 페이지로 이동해야 하는데, 마이페이지가 그대로 표시됨
- 사용자 정보가 없는 상태(`user === null`)에서도 페이지가 렌더링됨

### 기대 동작
- 로그아웃 후 마이페이지 접근 시 자동으로 로그인 페이지(`/login`)로 리다이렉트
- 인증되지 않은 사용자는 마이페이지에 접근 불가

---

## 🔍 근본 원인 분석

### 1. 라우팅 구조 분석

**코드 위치**: `src/App.tsx:122`

```typescript
<Route path="/" element={<AppLayout />}>
  {/* ... */}
  {/* 마이페이지 */}
  <Route path="my" element={<My />} />
</Route>
```

**문제점**:
- 마이페이지가 `AppLayout` 안에 있지만 `ProtectedRoute`로 보호되지 않음
- 관리자 페이지(`/admin/*`)는 `ProtectedRoute`로 보호되지만, 마이페이지는 보호되지 않음

### 2. My 컴포넌트 분석

**코드 위치**: `src/pages/app/My.tsx:16-33`

**수정 전 코드**:
```typescript
export function My() {
  const { user, signOut } = useAuth();
  const navigate = useNavigate();

  // ❌ 인증 체크 없음
  // ❌ user가 null이어도 렌더링됨

  const userName = user?.displayName || "사용자";  // 기본값으로 처리
  const userEmail = user?.email || "";  // 빈 문자열로 처리
  // ...
}
```

**문제점**:
1. **인증 체크 없음**: `user`가 `null`인지 확인하지 않음
2. **조건부 렌더링 없음**: `user`가 없어도 페이지가 렌더링됨
3. **기본값 처리**: `user?.displayName || "사용자"`로 인해 사용자 정보가 없어도 "사용자"로 표시됨
4. **로딩 상태 미처리**: `loading` 상태를 확인하지 않음

### 3. 다른 페이지와의 비교

#### 관리자 페이지 (보호됨)
```typescript
<Route
  path="/admin"
  element={
    <ProtectedRoute roles={["owner", "admin"]}>
      <AdminLayout />
    </ProtectedRoute>
  }
>
```

#### 마이페이지 (보호되지 않음)
```typescript
<Route path="my" element={<My />} />  // ❌ ProtectedRoute 없음
```

### 4. 로그아웃 프로세스 분석

**코드 위치**: `src/contexts/AuthContext.tsx:271-278`

```typescript
const signOut = async () => {
  if (USE_FIREBASE && auth) {
    await firebaseSignOut(auth);
  } else {
    localStorage.removeItem('mockUser');
  }
  setUser(null);  // ✅ user 상태는 null로 설정됨
};
```

**동작**:
1. Firebase Auth 로그아웃 또는 localStorage 정리
2. `setUser(null)` 호출로 상태 업데이트
3. **하지만 마이페이지는 리렌더링되어도 인증 체크를 하지 않음**

### 5. 문제 발생 시나리오

#### 시나리오 A: 로그아웃 후 마이페이지 접근

1. 사용자가 로그아웃 버튼 클릭
2. `signOut()` 호출 → `setUser(null)` 실행
3. `navigate('/')` 호출로 홈으로 이동
4. 사용자가 하단 네비게이션에서 "마이" 탭 클릭
5. `/my` 경로로 이동
6. `My` 컴포넌트 렌더링
7. **인증 체크 없음** → `user`가 `null`이어도 렌더링됨
8. 결과: 빈 사용자 정보로 마이페이지 표시 ❌

#### 시나리오 B: 직접 URL 접근

1. 로그아웃 상태에서 브라우저 주소창에 `/my` 입력
2. `My` 컴포넌트 렌더링
3. **인증 체크 없음** → `user`가 `null`이어도 렌더링됨
4. 결과: 빈 사용자 정보로 마이페이지 표시 ❌

## 🎯 근본 원인 요약

### 1. 라우팅 보호 누락

| 페이지 | 보호 여부 | 방법 |
|--------|----------|------|
| **관리자 페이지** (`/admin/*`) | ✅ 보호됨 | `ProtectedRoute` 사용 |
| **마이페이지** (`/my`) | ❌ 보호 안 됨 | `ProtectedRoute` 없음 |

### 2. 컴포넌트 레벨 인증 체크 누락

- `My` 컴포넌트가 `user` 상태를 확인하지 않음
- `user`가 `null`이어도 기본값으로 처리하여 렌더링됨

### 3. 일관성 부족

- 관리자 페이지는 `ProtectedRoute`로 보호
- 마이페이지는 보호되지 않음
- 사용자 경험의 일관성 부족

## ✅ 해결 방법

### 적용된 수정 사항

#### `src/pages/app/My.tsx` 수정

**수정 전**:
```typescript
export function My() {
  const { user, signOut } = useAuth();
  const navigate = useNavigate();
  // 인증 체크 없음
}
```

**수정 후**:
```typescript
import { Navigate } from "react-router-dom";
import { LoadingSkeleton } from "../../components/shared/LoadingSkeleton";

export function My() {
  const { user, signOut, loading } = useAuth();
  const navigate = useNavigate();

  // 로딩 중
  if (loading) {
    return (
      <div className="min-h-screen bg-[#F9F6F3] flex items-center justify-center">
        <LoadingSkeleton />
      </div>
    );
  }

  // 로그인하지 않은 경우 로그인 페이지로 리다이렉트
  if (!user) {
    return <Navigate to="/login" replace />;
  }

  // 인증된 사용자만 아래 코드 실행
  // ...
}
```

### 해결 효과

1. **인증 체크 추가**: `user`가 `null`이면 로그인 페이지로 리다이렉트
2. **로딩 상태 처리**: 인증 상태 확인 중 로딩 표시
3. **일관성 확보**: 관리자 페이지와 동일한 인증 체크 패턴 적용

## 🔄 대안 해결 방법 (비교)

### 방법 1: 컴포넌트 레벨 인증 체크 (적용됨) ✅

**장점**:
- 간단하고 직관적
- 페이지별로 세밀한 제어 가능
- 기존 라우팅 구조 변경 불필요

**단점**:
- 각 페이지마다 인증 체크 코드 중복 가능
- 일관성 유지가 어려울 수 있음

### 방법 2: 라우팅 레벨 보호 (미적용)

**장점**:
- 중앙 집중식 관리
- 일관성 보장
- 코드 중복 최소화

**단점**:
- 라우팅 구조 변경 필요
- 모든 페이지에 적용하면 공개 페이지도 보호될 수 있음

**예시**:
```typescript
<Route path="my" element={
  <ProtectedRoute>
    <My />
  </ProtectedRoute>
} />
```

### 방법 3: AppLayout 레벨 보호 (미적용)

**장점**:
- AppLayout 내 모든 페이지 보호
- 한 번만 설정하면 됨

**단점**:
- 홈, 메뉴 등 공개 페이지도 보호될 수 있음
- 세밀한 제어 불가

3. 데이터는 표시되지 않지만 빈 페이지가 표시됨

### 우선순위: **중간** 🟡

**이유**:
