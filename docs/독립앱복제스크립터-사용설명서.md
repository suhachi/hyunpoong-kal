## 1. 스크립터 소개

### 1-1. 무엇인가요?

**완전 독립 앱 복제 스크립터**는 현풍닭칼국수 PWA 템플릿을 기반으로,  
새 가게 전용 앱을 완전히 독립된 형태로 복제하는 자동화 도구입니다.

### 1-2. 왜 필요한가요?

- **멀티 스토어 확장**: 새 가게 추가 시 수동 작업 최소화
- **일관성 유지**: 모든 가게 앱이 동일한 구조로 시작
- **시간 절약**: 복제 작업을 수 분 내에 완료
- **실수 방지**: 자동화를 통한 설정 오류 최소화

### 1-3. 무엇을 하나요?

스크립터는 다음 작업을 자동으로 수행합니다:

1. ✅ 새 디렉터리 생성 (`clones/{storeId}/`)
2. ✅ 원본 코드/설정 파일 복사
3. ✅ `package.json` 자동 수정 (name, version, description)
4. ✅ `.env.local.example` 생성 (Firebase 설정 템플릿)
5. ✅ 가게 정보 초기화 (`src/config/env.ts`)
6. ✅ 메뉴 데이터 초기화 (빈 배열)
7. ✅ 점주용 README 생성
8. ✅ 상세 설정 가이드 생성

### 1-4. 무엇을 하지 않나요?

다음 작업은 **수동으로** 수행해야 합니다:

- ❌ Firebase 프로젝트 생성
- ❌ Firebase Hosting 도메인 연결
- ❌ Firestore 보안 규칙 설정
- ❌ 초기 관리자 계정 생성
- ❌ 실제 배포

> 💡 **참고**: 이러한 작업들은 생성된 가이드 문서에 상세히 안내되어 있습니다.

## 2. 사전 준비사항

### 2-1. 시스템 요구사항

- **Node.js**: 18.0.0 이상
- **npm**: 9.0.0 이상 (또는 yarn, pnpm)
- **운영체제**: Windows, macOS, Linux 모두 지원
- **터미널**: PowerShell (Windows), Terminal (macOS/Linux)

### 2-2. 필요한 권한

- 현재 디렉터리에 파일 생성/수정 권한
- `clones/` 디렉터리 생성 권한
- npm 패키지 설치 권한

### 2-3. 사전 확인 사항

스크립터를 실행하기 전에 다음을 확인하세요:

```bash
# 1. Node.js 버전 확인
node --version
# 예상 출력: v18.x.x 이상

# 2. npm 버전 확인
npm --version
# 예상 출력: 9.x.x 이상

# 3. 현재 디렉터리 확인 (프로젝트 루트여야 함)
pwd  # Linux/Mac
cd   # Windows PowerShell

# 4. Git 상태 확인 (선택사항, 안전 확인용)
git status
```

### 2-4. 필요한 정보 준비

스크립터 실행 시 다음 정보를 입력해야 합니다:

1. **스토어 ID** (`storeId`)
   - 예: `hp_store_gangnam`, `hp_store_incheon`
   - 형식: 소문자, 숫자, 언더스코어만 사용 가능
   - 용도: 디렉터리명, 패키지명에 사용

2. **가게 이름** (`storeName`)
   - 예: `현풍닭칼국수 강남점`, `현풍닭칼국수 인천점`
   - 용도: 앱 이름, 문서에 표시

3. **사장님 이름** (`ownerName`)
   - 예: `김사장`, `홍길동`
   - 용도: 앱 설정, 문서에 표시

4. **기본 로케일** (`defaultLocale`)
   - 기본값: `ko-KR`
   - 용도: 앱 기본 언어 설정

5. **기본 도메인** (`baseDomain`) - 선택사항
   - 예: `https://gangnam.hyunpoong.com`
   - 용도: 나중에 설정 가능

## 3. 설치 및 설정

### 3-1. 의존성 확인

스크립터 실행에 필요한 패키지가 이미 설치되어 있는지 확인:

```bash
# package.json 확인
cat package.json | grep -E "fs-extra|prompts|tsx"
```

필요한 패키지:
- `fs-extra`: 파일 복사/디렉터리 생성
- `prompts`: CLI 질문 인터페이스
- `tsx`: TypeScript 실행

### 3-2. 의존성 설치 (필요한 경우)

만약 패키지가 설치되어 있지 않다면:

```bash
npm install
```

또는 개별 설치:

```bash
npm install --save-dev fs-extra prompts tsx @types/fs-extra
```

### 3-3. 스크립트 파일 확인

스크립트 파일이 존재하는지 확인:

```bash
# Windows PowerShell
Test-Path scripts\create-independent-store.ts

# Linux/Mac
test -f scripts/create-independent-store.ts && echo "존재함" || echo "없음"
```


스크립터를 실행하면 다음 순서로 진행됩니다:

5. **최종 확인**
   - 작업 진행 여부 확인

## 5. 단계별 상세 가이드

### 5-1. 스토어 ID 입력

**질문**: `스토어 ID를 입력하세요 (예: hp_store_gangnam)`

**입력 예시**:
```
hp_store_gangnam
```

**유효한 형식**:
- ✅ `hp_store_gangnam`
- ✅ `hp_store_001`
- ✅ `store_incheon`
- ❌ `HP_Store_Gangnam` (대문자 불가)
- ❌ `hp-store-gangnam` (하이픈 불가)
- ❌ `hp store gangnam` (공백 불가)

**검증 규칙**:
- 소문자, 숫자, 언더스코어(`_`)만 사용 가능
- 빈 값 불가
- 최소 3자 이상 권장

**용도**:
- 디렉터리명: `clones/hp_store_gangnam/`
- 패키지명: `hp-store-gangnam`
- 문서 파일명: `STORE_SETUP_GUIDE_hp_store_gangnam.md`

### 5-2. 가게 이름 입력

**질문**: `가게 이름을 입력하세요 (예: 현풍닭칼국수 강남점)`

**입력 예시**:
```
현풍닭칼국수 강남점
```

**유효한 형식**:
- ✅ `현풍닭칼국수 강남점`
- ✅ `현풍닭칼국수 인천점`
- ✅ `현풍닭칼국수 부산해운대점`
- ❌ (빈 값)

**용도**:
- 앱 이름 표시
- `package.json`의 `description`
- README 파일 제목
- `src/config/env.ts`의 `APP_CONFIG.name`

### 5-3. 사장님 이름 입력

**질문**: `사장님 이름을 입력하세요 (예: 홍길동)`

**입력 예시**:
```
김사장
```

**유효한 형식**:
- ✅ `김사장`
- ✅ `홍길동`
- ✅ `이철수`
- ❌ (빈 값)

**용도**:
- `src/config/env.ts`의 `APP_CONFIG.company`
- 설정 가이드 문서에 표시

### 5-4. 기본 로케일 입력

**질문**: `기본 로케일을 입력하세요`

**기본값**: `ko-KR`

**입력 예시**:
```
ko-KR
```

**다른 옵션** (향후 확장 가능):
- `en-US` (영어)
- `ja-JP` (일본어)
- `zh-CN` (중국어)

**용도**:
- 앱 기본 언어 설정
- 향후 다국어 지원 확장 시 사용

### 5-5. 기본 도메인 입력 (선택)

**질문**: `기본 도메인을 입력하세요 (선택, 나중에 설정 가능)`

**기본값**: (빈 값)

**입력 예시**:
```
https://gangnam.hyunpoong.com
```

또는 빈 값으로 두기:
```
(Enter 키만 누르기)
```

**용도**:
- 향후 도메인 설정 시 참고용
- 현재는 선택사항

### 5-6. 중복 디렉터리 처리

만약 `clones/{storeId}/` 디렉터리가 이미 존재하는 경우:

**질문**: `clones/hp_store_gangnam 디렉터리가 이미 존재합니다. 덮어쓰시겠습니까? (기본값: 아니오)`

**주의**: 덮어쓰기를 선택하면 기존 디렉터리의 모든 내용이 삭제됩니다!

## 6. 실전 예시 시나리오

### 시나리오 1: 강남점 신규 오픈

**상황**: 현풍닭칼국수 강남점이 새로 오픈하여 전용 앱이 필요함

**단계별 실행**:

```bash
# 1. 스크립터 실행
npx tsx scripts/create-independent-store.ts

# 2. 질문에 답변
# 스토어 ID: hp_store_gangnam
# 가게 이름: 현풍닭칼국수 강남점
# 사장님: 김사장
# 기본 로케일: ko-KR
# 기본 도메인: (빈 값)

# 3. 생성된 디렉터리로 이동
cd clones/hp_store_gangnam

# 4. 의존성 설치
npm install

# 5. 환경변수 파일 생성
# Windows PowerShell
Copy-Item .env.local.example .env.local

# Linux/Mac
cp .env.local.example .env.local

# 6. .env.local 파일 편집 (Firebase 설정값 입력)
# Windows: notepad .env.local
# Mac/Linux: nano .env.local

# 7. 빌드 테스트
npm run build

# 8. Firebase 배포 (Firebase 프로젝트 생성 후)
firebase deploy --only hosting
```

### 시나리오 2: 인천점 추가 (기존 디렉터리 존재)

**상황**: 인천점 앱을 생성하려는데, 실수로 같은 스토어 ID로 이미 생성했음

**단계별 실행**:

```bash
# 1. 스크립터 실행
npx tsx scripts/create-independent-store.ts

# 2. 질문에 답변
# 스토어 ID: hp_store_incheon
# 가게 이름: 현풍닭칼국수 인천점
# 사장님: 이사장
# 기본 로케일: ko-KR
# 기본 도메인: (빈 값)

# 3. 중복 확인 질문이 나타남
# "clones/hp_store_incheon 디렉터리가 이미 존재합니다. 덮어쓰시겠습니까?"
# → Y 선택 (기존 내용 삭제 후 새로 생성)
# 또는 N 선택 (작업 취소, 다른 스토어 ID 사용)

# 4. 이후는 시나리오 1과 동일
```

### 시나리오 3: 여러 가게 일괄 생성

**상황**: 3개 가게를 한 번에 생성해야 함

**단계별 실행**:

```bash
# 가게 1: 강남점
npx tsx scripts/create-independent-store.ts
# 입력: hp_store_gangnam, 현풍닭칼국수 강남점, 김사장

# 가게 2: 인천점
npx tsx scripts/create-independent-store.ts
# 입력: hp_store_incheon, 현풍닭칼국수 인천점, 이사장

# 가게 3: 부산점
npx tsx scripts/create-independent-store.ts
# 입력: hp_store_busan, 현풍닭칼국수 부산점, 박사장
```

각 가게마다 독립적으로 생성되므로 순서는 상관없습니다.

## 7. 생성된 파일 구조

### 7-1. 전체 구조


## 8. 문제 해결

### 8-1. 일반적인 오류

#### 오류 1: "Cannot find module 'fs-extra'"

**원인**: 필요한 패키지가 설치되지 않음

**해결 방법**:
```bash
npm install
```

또는:
```bash
npm install --save-dev fs-extra prompts tsx @types/fs-extra
```

#### 오류 2: "Cannot find module 'prompts'"

**원인**: prompts 패키지가 설치되지 않음

**해결 방법**:
```bash
npm install --save-dev prompts
```

#### 오류 3: "tsx: command not found"

**원인**: tsx가 전역 설치되지 않았거나 npx를 사용하지 않음

**해결 방법**:
```bash
# 방법 1: npx 사용 (권장)
npx tsx scripts/create-independent-store.ts

# 방법 2: 전역 설치
npm install -g tsx
tsx scripts/create-independent-store.ts
```

#### 오류 4: "EACCES: permission denied"

**원인**: 디렉터리 생성 권한 없음

**해결 방법**:
```bash
# Linux/Mac: 권한 확인
ls -la clones/

# Windows: 관리자 권한으로 실행
# PowerShell을 관리자 권한으로 실행 후 다시 시도
```

#### 오류 5: "ENOENT: no such file or directory"

**원인**: 스크립트 파일 경로가 잘못됨

**해결 방법**:
```bash
# 프로젝트 루트 디렉터리에서 실행 확인
pwd  # Linux/Mac
cd   # Windows PowerShell

# 스크립트 파일 존재 확인
ls scripts/create-independent-store.ts  # Linux/Mac
Test-Path scripts\create-independent-store.ts  # Windows
```

### 8-2. 복제 중 오류

#### 오류 6: 복제 중 "Error: EEXIST: file already exists"

**원인**: 파일 복사 중 충돌

**해결 방법**:
1. 기존 디렉터리 삭제:
   ```bash
   # Windows PowerShell
   Remove-Item -Recurse -Force clones\hp_store_gangnam
   
   # Linux/Mac
   rm -rf clones/hp_store_gangnam
   ```
2. 스크립터 다시 실행

#### 오류 7: 복제는 성공했지만 빌드 실패

**원인**: 생성된 앱의 의존성 문제

**해결 방법**:
```bash
cd clones/hp_store_gangnam
rm -rf node_modules package-lock.json  # Linux/Mac
# 또는
Remove-Item -Recurse -Force node_modules, package-lock.json  # Windows

npm install
npm run build
```

### 8-3. 입력 오류

#### 오류 8: "스토어 ID는 소문자, 숫자, 언더스코어만 사용 가능합니다"

**원인**: 스토어 ID에 잘못된 문자가 포함됨

**해결 방법**:
- 대문자 → 소문자로 변경
- 하이픈(`-`) → 언더스코어(`_`)로 변경
- 공백 제거

**예시**:
```
❌ HP-Store-Gangnam
✅ hp_store_gangnam

❌ hp store gangnam
✅ hp_store_gangnam
```

#### 오류 9: "필수 입력값이 누락되었습니다"

**원인**: 필수 항목(storeId, storeName, ownerName, defaultLocale) 중 하나가 비어있음

**해결 방법**:
- 모든 필수 항목에 값을 입력
- 빈 값으로 두지 않기

### 8-4. 성능 문제

#### 문제 10: 복제가 매우 느림

**원인**: `src/` 디렉터리가 매우 큼

**해결 방법**:
- 정상적인 현상입니다. `src/` 디렉터리 전체를 복사하므로 시간이 걸릴 수 있습니다.
- 진행 중에는 기다려주세요.
- 일반적으로 1-2분 내에 완료됩니다.

## 9. FAQ

### Q1: 원본 프로젝트는 안전한가요?

**A**: 네, 완전히 안전합니다. 스크립터는 `clones/` 디렉터리 아래에만 파일을 생성하며, 원본 프로젝트는 전혀 수정하지 않습니다.

### Q2: 여러 가게를 동시에 생성할 수 있나요?

**A**: 네, 가능합니다. 각 가게마다 독립적으로 생성되므로 순서대로 실행하면 됩니다.

### Q3: 생성된 앱을 수정해도 원본에 영향이 있나요?

**A**: 없습니다. 완전히 독립된 프로젝트이므로 서로 영향을 주지 않습니다.

### Q4: 스토어 ID를 나중에 변경할 수 있나요?

**A**: 가능하지만, 디렉터리명과 패키지명이 변경되므로 주의가 필요합니다.  
가능하면 처음부터 올바른 스토어 ID를 사용하는 것을 권장합니다.

### Q5: 생성된 앱에서 원본의 메뉴 데이터를 사용할 수 있나요?

**A**: 복제 시점에는 메뉴 데이터가 빈 배열로 초기화됩니다.  
원본의 메뉴 데이터를 사용하려면 수동으로 복사해야 합니다.  
하지만 일반적으로는 각 가게마다 다른 메뉴를 사용하므로, 관리자 대시보드에서 새로 등록하는 것을 권장합니다.

### Q6: Firebase 설정은 어떻게 하나요?

**A**: 생성된 `docs/STORE_SETUP_GUIDE_{storeId}.md` 파일에 상세한 가이드가 있습니다.  
또는 `README_STORE.md`를 참고하세요.

### Q7: 생성된 앱을 Git에 커밋해야 하나요?

**A**: 선택사항입니다. 각 가게 앱은 독립적인 프로젝트이므로, 필요에 따라 별도의 Git 리포지토리를 만들 수 있습니다.

### Q8: 스크립터를 수정할 수 있나요?

**A**: 네, `scripts/create-independent-store.ts` 파일을 수정할 수 있습니다.  
다만 수정 전에 백업을 권장합니다.

### Q9: Windows에서 실행할 수 있나요?

**A**: 네, Windows, macOS, Linux 모두 지원합니다.

### Q10: 생성된 앱의 버전은 어떻게 되나요?

**A**: 모든 새 앱은 `0.1.0`으로 시작합니다. 원본 버전과 독립적으로 관리됩니다.

### 10-2. 배치 생성 스크립트

여러 가게를 한 번에 생성하는 배치 스크립트를 만들 수 있습니다:

```bash
#!/bin/bash
# create-multiple-stores.sh

stores=(
  "hp_store_gangnam:현풍닭칼국수 강남점:김사장"
  "hp_store_incheon:현풍닭칼국수 인천점:이사장"
  "hp_store_busan:현풍닭칼국수 부산점:박사장"
)

for store in "${stores[@]}"; do
  IFS=':' read -r storeId storeName ownerName <<< "$store"
  echo "Creating $storeId..."
  # 스크립터를 비대화형으로 실행하는 방법 필요
done
```

> ⚠️ **주의**: 현재 스크립터는 대화형(prompts)이므로, 배치 생성은 스크립터를 수정해야 합니다.

### 10-3. 환경변수 기반 실행

스크립터를 수정하여 환경변수로 입력값을 받을 수 있도록 할 수 있습니다:

## 11. 주의사항 및 제한사항

### 11-1. 주의사항

1. **원본 프로젝트 백업**
   - 스크립터는 원본을 수정하지 않지만, 안전을 위해 백업을 권장합니다.

2. **스토어 ID 중복 방지**
   - 같은 스토어 ID로 여러 번 생성하면 덮어쓰기 확인이 나타납니다.
   - 기존 데이터가 삭제될 수 있으므로 주의하세요.

3. **디스크 공간**
   - 각 가게 앱은 전체 소스 코드를 복사하므로 상당한 디스크 공간이 필요합니다.
   - 예: 원본이 100MB라면, 10개 가게 = 약 1GB

4. **Firebase 프로젝트**
   - 각 가게마다 별도의 Firebase 프로젝트가 필요합니다.
   - 스크립터는 Firebase 프로젝트를 생성하지 않습니다.

5. **메뉴 데이터**
   - 복제 시점에는 메뉴가 빈 상태입니다.
   - 각 가게에서 관리자 대시보드를 통해 메뉴를 등록해야 합니다.

### 11-2. 제한사항

1. **대화형 인터페이스**
   - 현재는 대화형(prompts)만 지원합니다.
   - 비대화형/배치 모드는 지원하지 않습니다.

2. **템플릿 업데이트**
   - 원본 템플릿이 업데이트되어도 기존에 생성된 앱에는 자동으로 반영되지 않습니다.
   - 수동으로 업데이트하거나 새로 생성해야 합니다.

3. **멀티 테넌트 미지원**
   - 현재는 완전 독립 앱만 생성합니다.
   - 단일 앱에서 여러 가게를 관리하는 멀티 테넌트 방식은 지원하지 않습니다.

4. **자동 배포 미지원**
   - 스크립터는 코드 복제만 수행합니다.
   - Firebase 배포는 수동으로 수행해야 합니다.

### 11-3. 알려진 이슈

현재 알려진 이슈는 없습니다.  
문제를 발견하면 이슈를 등록해주세요.
