## 📋 작업 개요

### 목표

v1.0 Firebase 실연동을 위한 **Firestore 스키마/타입/컬렉션 헬퍼의 "뼈대"** 구축. 메뉴/주문 중심으로 Firestore 컬렉션 경로/타입 정의 및 Firestore 초기 rules / indexes 기본 골격 준비.

### 작업 범위

- ✅ Firestore 클라이언트 초기화 파일 정리 (`src/lib/firebase.ts`)
- ✅ Firestore 스키마/타입/경로 헬퍼 정의 (`src/lib/firebase/firestore-schema.ts`)
- ✅ Firestore 보안 규칙 템플릿 정리 (`firestore.rules`)
- ✅ Firestore 인덱스 템플릿 정리 (`firestore.indexes.json`)
- ✅ `firebase.json`에 Firestore 섹션 추가
- ✅ 빌드 검증 완료

**중요**: 이번 스텝에서는 **API 로직(createOrder, getMenus 등)에 Firestore 호출을 추가하지 않음**. Mock ↔ Firebase 모드 분기 로직, 실제 Firestore read/write 구현은 STEP 3 이후.

## 🔧 변경된 파일 목록

### 1. `src/lib/firebase.ts` (수정)

**변경 내용**:
- `getApps()`, `getApp()` import 추가
- 중복 초기화 방지 로직 추가 (`getApps().length > 0 ? getApp() : initializeApp(...)`)
- v1.0 주석 추가

**변경 전**:
```typescript
import { initializeApp, type FirebaseApp } from 'firebase/app';
// ...
if (USE_FIREBASE) {
  app = initializeApp(firebaseConfig);
  // ...
}
```

**변경 후**:
```typescript
import { initializeApp, getApps, getApp, type FirebaseApp } from 'firebase/app';
// ...
if (USE_FIREBASE) {
  // 이미 초기화된 앱이 있으면 재사용, 없으면 새로 초기화
  app = getApps().length > 0 ? getApp() : initializeApp(firebaseConfig);
  // ...
}
```

**효과**:
- Firebase 앱 중복 초기화 방지
- Hot Module Replacement (HMR) 환경에서 안전하게 동작
- 테스트 환경에서도 안전하게 재사용 가능

### 2. `src/lib/firebase/firestore-schema.ts` (신규 생성)

**파일 경로**: `src/lib/firebase/firestore-schema.ts`

**내용 구성**:

#### 2-1. Firestore 문서 타입 정의

1. **`StoreDoc`**: 매장 기본 정보 문서 타입
   - 컬렉션: `stores/{storeId}`
   - 주요 필드: `storeId`, `name`, `address`, `phone`, `businessHours`, `isOpen`, `deliveryAvailable`, `settings`, `createdAt`, `updatedAt`

2. **`MenuDoc`**: 메뉴 정보 문서 타입
   - 컬렉션: `stores/{storeId}/menus/{menuId}`
   - 주요 필드: `menuId`, `storeId`, `category`, `name`, `price`, `description`, `imageUrl`, `imagePath`, `badges`, `options`, `optionGroups`, `allergens`, `origin`, `isAvailable`, `availableHours`, `order`, `createdAt`, `updatedAt`

3. **`OrderDoc`**: 주문 정보 문서 타입
   - 컬렉션: `stores/{storeId}/orders/{orderId}`
   - 주요 필드: `orderId`, `storeId`, `userId`, `items`, `subtotal`, `discount`, `couponId`, `deliveryFee`, `finalAmount`, `deliveryType`, `deliveryAddress`, `phone`, `email`, `requests`, `status`, `payment`, `timeline`, `cashReceipt`, `taxInvoice`, `createdAt`, `updatedAt`

#### 2-2. Firestore 컬렉션/문서 경로 헬퍼

- `storesCollection(dbInstance?)`: stores 컬렉션 참조
- `storeDocRef(storeId, dbInstance?)`: 매장 문서 참조
- `storeMenusCollection(storeId, dbInstance?)`: 매장 메뉴 컬렉션 참조
- `storeMenuDocRef(storeId, menuId, dbInstance?)`: 매장 메뉴 문서 참조
- `storeOrdersCollection(storeId, dbInstance?)`: 매장 주문 컬렉션 참조
- `storeOrderDocRef(storeId, orderId, dbInstance?)`: 매장 주문 문서 참조

**특징**:
- 모든 헬퍼 함수는 `dbInstance: Firestore = db` 파라미터를 받아 테스트 환경에서 다른 Firestore 인스턴스를 주입 가능
- 기존 도메인 타입(`OrderStatus`, `PaymentMethod`, `PaymentStatus`, `OrderItem`, `DeliveryAddress`, `MenuCategory`, `MenuBadge`) 재사용
- `firebase/firestore`의 `Timestamp` 타입 사용

#### 2-3. 타입 가드 함수 (향후 확장용)

- `isValidOrderDoc(doc)`: OrderDoc 유효성 검증 (TODO: STEP 3에서 구현)
- `isValidMenuDoc(doc)`: MenuDoc 유효성 검증 (TODO: STEP 3에서 구현)

### 3. `firestore.rules` (신규 생성 - 루트)

**파일 경로**: 프로젝트 루트 `firestore.rules`

**내용**:
```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // v1.0 개발용 규칙 (전부 허용)
    // ⚠️ 주의: 이 규칙은 개발 단계용입니다.
    // 프로덕션 배포 전에는 반드시 아래 규칙을 엄격한 인증/권한 기반 규칙으로 교체해야 합니다.
    match /{document=**} {
      allow read, write: if true;
    }
  }
}
```

**특징**:
- 개발 단계용 전부 허용 규칙
- 프로덕션 전 교체 필요 주석 포함
- v1.0 설계 문서의 "개발용 규칙" 요구사항 충족

**참고**: 기존 `src/firestore.rules` 파일은 복잡한 프로덕션 규칙을 포함하고 있으나, 이번 STEP에서는 개발용 간단한 규칙을 루트에 생성. 향후 STEP에서 프로덕션 규칙으로 교체 예정.

const menusRef = storeMenusCollection('hyunpoong_main');

const ordersRef = storeOrdersCollection('hyunpoong_main');

// 주문 문서 참조
const orderRef = storeOrderDocRef('hyunpoong_main', 'order_001');
