## 1. 작업 개요

### 1.1 목적
Phase 2 Order-flow E2E 재작성을 위해 Cart.tsx에 data-testid 속성을 추가하여 텍스트/레이아웃 변경에 영향받지 않는 안정적인 테스트 환경을 구축한다.

### 1.2 배경
- Phase 1에서 Order-flow E2E가 텍스트 셀렉터(getByText) 의존으로 인해 flaky 발생
- TESTID_STRATEGY_OrderFlow_2025-Phase2.md 문서 작성 완료
- Cart 페이지가 Order-flow의 핵심 단계이므로 우선 적용

### 1.3 적용 범위
- 파일: `src/pages/app/Cart.tsx`
- 전략 문서: `docs/TESTID_STRATEGY_OrderFlow_2025-Phase2.md`

## 2. 구현 내역

### 2.1 적용된 testId 목록 (총 18개)

#### 페이지 레벨
1. **cart.page** - Cart 페이지 최상위 컨테이너
2. **cart.empty** - 빈 장바구니 상태 컨테이너

#### 헤더 영역
3. **cart.header** - 장바구니 헤더 ("장바구니" 타이틀, "N개 메뉴")

#### 아이템 목록 영역
4. **cart.items** - 장바구니 아이템 리스트 래퍼
5. **cart.item** - 개별 아이템 카드 (반복)
6. **cart.item.name** - 아이템 메뉴명
7. **cart.item.options** - 아이템 옵션 (면양/맵기/토핑)
8. **cart.item.quantity** - 아이템 수량 표시
9. **cart.item.quantity-decrease** - 수량 감소 버튼 (-)
10. **cart.item.quantity-increase** - 수량 증가 버튼 (+)
11. **cart.item.price** - 아이템 금액
12. **cart.item.remove** - 아이템 삭제 버튼 (휴지통 아이콘)

#### 주문 방식 영역
13. **cart.method** - 배달/포장 선택 섹션
14. **cart.method.radio-delivery** - 배달 라디오 버튼
15. **cart.method.radio-pickup** - 포장 라디오 버튼

#### 요청사항 영역
16. **cart.input.requests** - 요청사항 텍스트 입력

#### 결제 영역
17. **cart.summary** - 하단 고정 금액 요약 섹션
18. **cart.button.submit** - 결제하기 버튼

### 2.2 코드 변경 사항

#### Before (기존 코드 - 예시)
```tsx
<div className="pb-32">
  <div className="px-4 py-6 space-y-6">
    <div>
      <h1 className="text-2xl text-[#2E1C10] mb-1">장바구니</h1>
    </div>
    <RadioGroupItem value="delivery" id="delivery" />
    <Button onClick={() => navigate('/checkout')}>
      결제하기
    </Button>
  </div>
</div>
```

#### After (data-testid 적용)
```tsx
<div className="pb-32" data-testid="cart.page">
  <div className="px-4 py-6 space-y-6">
    <div data-testid="cart.header">
      <h1 className="text-2xl text-[#2E1C10] mb-1">장바구니</h1>
    </div>
    <RadioGroupItem value="delivery" id="delivery" data-testid="cart.method.radio-delivery" />
    <Button data-testid="cart.button.submit" onClick={() => navigate('/checkout')}>
      결제하기
    </Button>
  </div>
</div>
```

### 2.3 네이밍 규칙 준수

✅ **소문자 kebab-case:** 모든 testId는 소문자 + 하이픈 사용  
✅ **dot 분리:** `cart.method.radio-delivery` (영역.컴포넌트.의미)  
✅ **일관성:** TESTID_STRATEGY 문서와 100% 일치  
✅ **의미 명확성:** UI 텍스트에 의존하지 않고 역할 기반 명명

- 현재: `test.describe.skip('Order flow (Mock, payment OFF)')` 적용됨

### 3.2 Phase 2에서 가능해지는 안정적인 테스트 패턴

#### 기존 (flaky한 텍스트 셀렉터)
```typescript
// ❌ Phase 1 방식 (텍스트 변경 시 깨짐)
await page.getByText('주문 방식').waitFor({ state: 'visible' });
await page.locator('#pickup').click();
```

#### Phase 2 (안정적인 testId 셀렉터)
```typescript
// ✅ Phase 2 방식 (레이아웃/텍스트 변경에 강건)
await expect(page.getByTestId('cart.method')).toBeVisible();
await page.getByTestId('cart.method.radio-pickup').click();
await page.getByTestId('cart.button.submit').click();
```
