## 📋 작업 요약

요청하신 프롬프트에 따라 NICEPAY 결제 연동 구조를 테스트/실사용 전환이 용이하도록 정리하고, 주소 검색 기능을 공통 컴포넌트로 구현하여 통합했습니다. 기존 기능에 영향을 주지 않도록 안전하게 작업되었습니다.

---

## ✅ 구현 상세 내용

### 1. NICEPAY 결제 플로우 (Checkout & Return)

*   **`Checkout.tsx` 수정**:
    *   `PaymentMethod.APP_CARD` + `FEATURE_FLAGS.onlinePayment` 활성화 시에만 NICEPAY 로직이 실행됩니다.
    *   `src/lib/nicepay.ts`의 `initiatePayment` 함수를 사용하여 PG 인증 URL을 받아옵니다.
    *   보안을 위해 `authToken`을 `sessionStorage`에 `payment_auth_${orderId}` 키로 저장 후 PG 결제창으로 리다이렉트합니다.
    *   기존 `MEET_CARD`, `MEET_CASH` 결제 방식은 PG 연동 없이 주문만 생성하도록 유지했습니다.

*   **`PaymentReturn.tsx` 구현**:
    *   결제 성공 후 리다이렉트되는 페이지입니다.
    *   URL의 `orderId`를 기반으로 `sessionStorage`에서 `authToken`을 조회하여 `approvePayment`를 호출합니다. (보안 강화)
    *   승인 성공 시 주문 상세 페이지로, 실패 시 에러 메시지와 함께 장바구니로 이동합니다.

*   **`PaymentCancel.tsx` 구현**:
    *   사용자가 결제를 취소했을 때 보여지는 단순 안내 페이지입니다.

### 2. 주소 검색 공통 컴포넌트 (AddressSearch)

*   **`src/components/admin/AddressSearch.tsx` 구현**:
    *   Daum Postcode 서비스를 사용하는 재사용 가능한 컴포넌트입니다.
    *   `DeliveryAddress` 인터페이스(`{ address, detail, lat?, lng? }`)와 완벽하게 호환됩니다.
    *   Admin(`StoreInfoTab`)과 Customer(`Cart`) 양쪽에서 동일한 컴포넌트를 사용하여 유지보수성을 높였습니다.

### 3. 환경 설정 및 라우팅

*   **`src/config/env.ts`**:
    *   기존 `NICEPAY_CONFIG` 구조를 유지하면서 `FEATURE_FLAGS.onlinePayment`를 통해 결제 기능을 제어하도록 설정했습니다.
*   **`src/App.tsx`**:
    *   `/order/return`, `/order/cancel` 라우트를 Lazy Loading으로 추가하여 초기 로딩 성능을 고려했습니다.

### 4. 테스트 (E2E)

*   **신규 테스트 파일 추가**:
    *   `src/e2e/checkout-payment.spec.ts`: 결제 플로우 시나리오 (스텁)
    *   `src/e2e/address-search.spec.ts`: 주소 검색 컴포넌트 동작 시나리오 (스텁)
    *   기존 테스트 파일은 수정하지 않았습니다.
