## ⚠️ Mock 모드의 한계

### localStorage 기반 저장의 문제점

현재 `USE_FIREBASE = false` (Mock 모드)에서는 모든 데이터가 **브라우저의 localStorage**에 저장됩니다.

**핵심 문제:**
- **localStorage는 브라우저별로 완전히 독립적**
- PC 브라우저의 localStorage ≠ 모바일 브라우저의 localStorage
- 같은 도메인이라도 **기기/브라우저가 다르면 데이터가 공유되지 않음**

### 실제 동작 예시

```
PC (Chrome)에서 관리자가 메뉴 이미지 변경
  ↓
PC 브라우저의 localStorage에만 저장
  ↓
모바일 (Safari/Chrome)에서 메뉴 확인
  ↓
모바일 브라우저의 localStorage에서 데이터 로드
  ↓
❌ 변경사항이 반영되지 않음 (완전히 다른 저장소)
```

## 🔍 문제 확인 방법

### 콘솔 로그 확인

브라우저 콘솔에서 다음 로그를 확인:

```
[env] USE_FIREBASE: false
```

이 값이 `false`이면 Mock 모드입니다.

### localStorage 확인

**PC 브라우저:**
```javascript
// Chrome DevTools Console
localStorage.getItem('hyunpoong_mock_menus')
```

**모바일 브라우저:**
- 모바일에서도 동일한 키로 저장되지만, **완전히 별도의 저장소**

## ✅ 해결 방법

### 방법 1: 같은 기기에서 테스트 (임시 해결)

**PC에서 테스트:**
1. PC 브라우저에서 관리자 화면 (`/admin`) 접속
2. 메뉴 이미지 변경
3. **같은 PC 브라우저**에서 고객 앱 (`/`) 접속
4. 변경사항 확인

**모바일에서 테스트:**
1. 모바일 브라우저에서 관리자 화면 접속
2. 메뉴 이미지 변경
3. **같은 모바일 브라우저**에서 고객 앱 접속
4. 변경사항 확인

**한계:**
- PC에서 변경한 내용이 모바일에서 보이지 않음
- 모바일에서 변경한 내용이 PC에서 보이지 않음

### 방법 2: Firebase 모드로 전환 (권장, 미구현)

**현재 상태:**
- Firebase 모드는 아직 구현되지 않음
- 모든 API에 `TODO: Firestore 연동` 표시
- `USE_FIREBASE = true`로 설정하면 에러 발생

**필요한 작업:**
1. Firestore 컬렉션 구조 설계
2. 모든 API 함수에 Firestore 연동 구현
3. 이미지 저장을 Firebase Storage로 전환
4. 환경 변수 설정

**예상 소요 시간:**
- 메뉴 API만: 2-3시간
- 전체 API: 1-2일

### 방법 3: 임시 동기화 스크립트 (개발용)

**개념:**
- PC에서 변경 시 localStorage 데이터를 export
- 모바일에서 import하여 동기화

**구현 예시:**
```javascript
// PC에서 실행
const data = localStorage.getItem('hyunpoong_mock_menus');
console.log('복사할 데이터:', data);

// 모바일에서 실행
localStorage.setItem('hyunpoong_mock_menus', '복사한 데이터');
location.reload();
```

**한계:**
- 수동 작업 필요
- 실시간 동기화 불가
- 프로덕션 환경에서 사용 불가

## 💡 참고 사항

### localStorage vs Firestore

| 항목 | localStorage (Mock) | Firestore (Real) |
|------|---------------------|------------------|
| **저장 위치** | 브라우저별 독립 | 클라우드 공유 |
| **기기 간 동기화** | ❌ 불가능 | ✅ 자동 |
| **용량 제한** | ~5-10MB | 무제한 |
| **오프라인 지원** | ✅ 자동 | ⚠️ 설정 필요 |
| **실시간 업데이트** | ❌ 불가능 | ✅ 가능 |
| **프로덕션 사용** | ❌ 부적합 | ✅ 적합 |

### Mock 모드의 장점

- ✅ Firebase 설정 없이 개발 가능
- ✅ 오프라인에서도 동작
- ✅ 빠른 프로토타이핑
- ✅ 비용 없음

### Mock 모드의 단점

- ❌ 기기 간 데이터 공유 불가
- ❌ 용량 제한
- ❌ 실시간 동기화 불가
- ❌ 프로덕션 환경 부적합
