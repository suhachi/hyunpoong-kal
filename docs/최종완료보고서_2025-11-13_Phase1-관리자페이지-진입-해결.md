## 📋 해결 과정 요약

### 1차 문제: AuthContext와 getCurrentUser() 불일치
**원인**: 두 시스템이 다른 localStorage 키 사용
- `AuthContext`: `mockUser` (JSON 객체)
- `getCurrentUser()`: `mockRole` (문자열)

**해결**: T1-1 작업 완료
- `getCurrentUser()`를 `mockUser` 기반으로 통일
- `mockLogin/mockLogout`에서 `mockRole` 제거
- `AdminLayout`을 `useAuth()` 훅 사용으로 전환

### 2차 문제: 환경 변수 불일치
**원인**: `.env` 파일에서 `VITE_USE_FIREBASE=true` 설정

**해결**: T1-2 작업 시도
- `.env` 파일 수정: `VITE_USE_FIREBASE=false`
- 서버 재시작 (여러 차례)
- **실패**: 브라우저 캐시로 인해 적용 안 됨

### 3차 문제: 환경 변수 캐시
**원인**: Vite 환경 변수가 빌드 시점에 번들에 포함되어 캐시됨

**해결**: T1-3 작업 완료 (팀장 지시)
- `env.ts`에서 `USE_FIREBASE` 하드코딩 `false`
- `firebase.ts`에서 초기화 가드 추가
- `AuthContext`에 디버그 로그 강화

## 🎓 배운 교훈

### 1. 환경 변수 처리의 중요성
**문제**: Vite는 환경 변수를 빌드 시점에 번들에 포함
- `.env` 파일 수정 후 서버 재시작만으로는 적용 안 됨
- 브라우저 캐시와 무관하게 번들 자체에 값이 고정됨

**해결**: 
- 개발 중에는 코드 레벨에서 직접 제어
- 또는 `node_modules/.vite` 캐시 삭제 필요

### 2. 디버그 로그의 중요성
**효과**:
- 문제 지점을 정확히 파악
- Firebase 모드 vs Mock 모드 구분 명확
- localStorage 상태 실시간 확인

**추천**:
- 개발 모드에서는 적극적으로 로그 활용
- 프로덕션 빌드 시 `console.log` 자동 제거 설정

### 3. 단일 진실의 원천 (Single Source of Truth)
**원칙**:
- 인증 상태는 `AuthContext`가 유일한 출처
- 다른 유틸 함수들도 `AuthContext`에 의존
- 중복 체크 로직 제거

**효과**:
- 동기화 문제 원천 차단
- 코드 간결화 (~30 라인 감소)
- 유지보수성 향상
