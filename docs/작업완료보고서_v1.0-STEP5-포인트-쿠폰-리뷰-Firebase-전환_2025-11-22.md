## 📋 작업 개요

### 목표

v1.0 Firebase 실연동을 위한 **포인트/쿠폰/리뷰 시스템 Firebase 전환 + 트랜잭션 설계** 완료. 기존 Mock(localStorage) 기반이던 포인트/쿠폰/리뷰 기능을 Firestore로 전환하고, 향후 주문/리뷰 시에 적용될 트랜잭션 흐름을 설계 및 기본 구현.

### 작업 범위

- ✅ Firestore 스키마 확장 (PointsBalanceDoc, PointsTransactionDoc, CouponDoc, ReviewDoc)
- ✅ 포인트 API Firebase 전환 + 트랜잭션 구현 (`src/lib/points.api.ts`)
  - `getPointsBalance` (잔액 조회)
  - `earnPoints` (적립, 트랜잭션)
  - `spendPoints` (사용, 트랜잭션)
  - `getPointsHistory` (내역 조회)
  - `expirePoints` (만료 처리)
  - `adjustPoints` (관리자 조정)
  - `getAllPointsBalances` (관리자 전체 조회)
- ✅ 쿠폰 API Firebase 전환 (`src/lib/coupons.api.ts`)
  - `getCoupons` (목록 조회)
  - `getAvailableCoupons` (사용 가능한 쿠폰 조회)
  - `useCoupon` (쿠폰 사용)
  - `issueCoupon` (관리자 발급)
  - `getCouponStats` (통계)
  - `expireCoupons` (만료 처리)
- ✅ 리뷰 API Firebase 전환 (`src/lib/admin/reviews.api.ts`)
  - `getReviews` (목록 조회)
  - `getReviewStats` (통계)
  - `addReviewReply` (답글 작성)
  - `deleteReviewReply` (답글 삭제)
  - `hideReview` (숨김 처리)
  - `reportReview` (신고, 기본 구조만)
- ✅ 트랜잭션 설계 주석 추가 (주문 완료/취소/리뷰 작성 시 포인트 흐름)
- ✅ Mock 모드 완전 보전 (기존 로직 100% 유지)
- ✅ 빌드 검증 완료

**중요**: 이번 스텝에서는 **Cloud Functions 트리거까지 다 짜지 않고, 클라이언트/Firestore 기준 트랜잭션 흐름 설계 + 기본 구현**에 집중. 실제 이벤트 연동(주문 완료 시 자동 포인트 적립 등)은 STEP 7(Cloud Functions)에서 마무리 예정.

## 📊 트랜잭션 설계 요약

### 포인트 적립/사용 트랜잭션

**구조**:
```typescript
await runTransaction(db, async (tx) => {
  // 1. 잔액 문서 읽기
  const balanceRef = pointsBalanceDocRef(userId);
  const balanceSnap = await tx.get(balanceRef);
  
  // 2. 잔액 업데이트
  const nextBalance: PointsBalanceDoc = { ... };
  tx.set(balanceRef, nextBalance);
  
  // 3. 거래 문서 생성
  const txCol = storePointsTransactionsCollection(storeId);
  const txDocRef = doc(txCol);
  tx.set(txDocRef, txDoc);
});
```

**특징**:
- 원자성 보장: 잔액 업데이트와 거래 문서 생성이 동시에 성공/실패
- 일관성 보장: 동시 요청 시에도 데이터 일관성 유지

### 주문 완료 시 포인트 적립 흐름 (설계)

**시나리오**:
1. 주문 상태가 'completed'로 변경되는 순간
2. `earnPoints({ userId, storeId, amount, refKind: 'order', refId: orderId, note: '주문 적립' })` 호출
3. `runTransaction`으로 잔액 증가 + 거래 문서 생성

**실제 트리거 위치**:
- STEP 7: Cloud Functions `onUpdate(orders/{orderId})` 트리거에서 처리 예정

### 주문 취소 시 환불 흐름 (설계)

**시나리오**:
1. 주문 상태가 'cancelled'로 변경되는 순간
2. 필요 시 `spendPoints` 또는 별도 `refundPoints` 헬퍼로 환불 처리

**실제 트리거 위치**:
- STEP 7: Cloud Functions에서 처리 예정

### 리뷰 작성 시 포인트 적립 흐름 (설계)

**시나리오**:
1. `createReview` 성공 이후
2. `earnPoints({ userId, storeId, amount: REVIEW_BONUS, refKind: 'review', refId: reviewId, note: '리뷰 작성 적립' })` 호출
3. 사진 포함 여부에 따라 적립 포인트 차등 (사진: 200P, 텍스트: 100P)

**실제 트리거 위치**:
- STEP 7: Cloud Functions `onCreate(reviews/{reviewId})` 트리거에서 처리 예정
