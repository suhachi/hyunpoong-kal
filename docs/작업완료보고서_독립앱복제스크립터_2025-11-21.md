## 5. 사용 방법

### 기본 사용법

```bash
# 1. 스크립트 실행
npx tsx scripts/create-independent-store.ts

# 2. 질문에 답변
storeId: hp_store_gangnam
storeName: 현풍닭칼국수 강남점
ownerName: 김사장
defaultLocale: ko-KR
baseDomain: (선택, 빈값 가능)

# 3. 생성된 디렉터리로 이동
cd clones/hp_store_gangnam

# 4. 의존성 설치
npm install

# 5. 환경변수 파일 생성
cp .env.local.example .env.local

# 6. .env.local 파일 채우기 (Firebase 설정값)
# 7. 빌드 및 배포
npm run build
firebase deploy --only hosting
```

### 생성되는 구조

```
clones/{storeId}/
  ├─ package.json          # name/description 수정됨
  ├─ .env.local.example    # 새 가게용 템플릿
  ├─ README_STORE.md       # 새 사장님용 사용설명서
  ├─ docs/
  │   └─ STORE_SETUP_GUIDE_{storeId}.md
  ├─ public/               # 로고/아이콘은 템플릿 기본값
  ├─ src/                  # 현 버전 소스 전체 복사
  ├─ tsconfig.json
  ├─ vite.config.ts
  └─ ... (기타 설정 파일들)
```

## 6. 기대 효과

### 6-1. 비즈니스 가치

1. **멀티 스토어 확장 용이성**
   - 새 가게 추가 시 수동 작업 최소화
   - 일관된 앱 구조 유지
   - 각 가게별 독립 운영 가능

2. **운영 효율성 향상**
   - 복제 시간 단축 (수동 작업 대비 90% 이상 시간 절약)
   - 실수 방지 (자동화를 통한 설정 오류 최소화)
   - 표준화된 배포 프로세스

3. **점주 온보딩 개선**
   - 자동 생성된 상세 가이드로 초기 설정 용이
   - 체크리스트 기반 단계별 진행
   - 문제 해결 가이드 포함

### 6-2. 기술적 가치

1. **완전 독립성 보장**
   - 원본 리포와 완전히 분리된 코드베이스
   - 각 가게별 독립적인 Firebase 프로젝트
   - 데이터 혼선 방지

2. **유지보수성 향상**
   - 템플릿 업데이트 시 새 가게에만 영향
   - 기존 가게 앱은 독립적으로 운영
   - 버전 관리 용이

3. **확장성**
   - 새로운 가게 추가 시 스크립트만 실행
   - 템플릿 개선 시 새 가게에 자동 반영
   - 멀티 스토어 확장 기반 마련

## 9. 주의사항

### ⚠️ 스크립트가 자동으로 하지 않는 것

다음 항목은 점주/운영자가 수동으로 수행해야 합니다:

1. **Firebase 콘솔에서 새 프로젝트 생성**
2. **Firebase Hosting 도메인 연결**
3. **실제 카드 결제 PG 연결**
4. **Firestore 보안 규칙 설정**
5. **Firebase Auth 초기 관리자 계정 생성**

이러한 항목들은 생성된 `STORE_SETUP_GUIDE_{storeId}.md`에 상세히 안내되어 있습니다.
