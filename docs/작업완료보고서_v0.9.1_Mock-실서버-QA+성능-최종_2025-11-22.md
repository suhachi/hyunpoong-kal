## 3. Admin 보안/인증 개선

### 발견된 문제 요약

1. **`/admin/dashboard` 진입 실패**
   - `/admin/dashboard` 경로로 직접 접근 시 진입 불가
   - 명시적 라우트가 없어서 접근 불가 상태

2. **인증 보호 불일치 (보안 취약점)**
   - `/admin/dashboard`는 로그인 화면 표시 (정상)
   - 다른 `/admin/*` 경로들(`/admin/menus`, `/admin/orders` 등)은 로그인 없이 접근 가능 (문제)
   - `/admin`은 대시보드로 바로 진입 (문제)

### 원인 요약

**React Router의 중첩 라우팅에서 `ProtectedRoute`가 자식 라우트까지 완전히 보호하지 못함**

- `ProtectedRoute`가 부모 라우트(`/admin`)의 `element`에만 적용됨
- 자식 라우트들(`/admin/menus`, `/admin/orders` 등)이 직접 접근될 때 `ProtectedRoute`가 완전히 작동하지 않을 수 있음
- `AdminLayout`이 렌더링된 후 `<Outlet />`을 통해 자식 라우트가 렌더링되는데, 이 시점에 인증 체크가 누락될 수 있음

### 해결 내용

1. **`/admin/dashboard` 명시 라우트 추가**
   - `src/App.tsx`에 `<Route path="dashboard" element={<Dashboard />} />` 추가
   - `/admin/dashboard` 경로로 직접 접근 가능하도록 수정

2. **AdminLayout useEffect 기반 이중 인증 체크**
   - `src/pages/admin/_layout/AdminLayout.tsx`에 `useEffect`로 `user` 상태 모니터링 추가
   - `user`가 없으면 자동으로 `/login`으로 리다이렉트
   - `ProtectedRoute` + `AdminLayout` 이중 보호 메커니즘 구현

3. **ProtectedRoute 로깅 강화**
   - `src/components/shared/ProtectedRoute.tsx`에서 `console.log` → `console.warn`으로 변경
   - 리다이렉트 전 상세 로그 추가 (원래 접근하려던 경로 출력)

### 효과

**모든 `/admin/*` 경로가 동일하게 보호되며, 로그인 없이 접근 시 자동으로 로그인 페이지로 리다이렉트됩니다.** `ProtectedRoute`와 `AdminLayout`의 이중 보호 메커니즘으로 React Router의 중첩 라우팅 구조에서도 안전하게 인증을 보장합니다. 보안 취약점이 완전히 제거되었고, 사용자 경험의 일관성도 개선되었습니다.

## 4. Lighthouse 모바일 성능 결과

### 경로별 성능 점수 요약

| 경로               | Performance | FCP    | LCP    | TBT   | Speed Index | CLS     |
|--------------------|------------|--------|--------|-------|-------------|---------|
| `/`                | 98         | 1.8 s  | 2.0 s  | 30 ms | 1.8 s       | 0       |
| `/menu`            | 98         | 1.9 s  | 2.0 s  | 60 ms | 1.9 s       | 0       |
| `/order-history`   | 98         | 1.9 s  | 2.0 s  | 30 ms | 1.9 s       | 0.021   |
| `/admin`           | 95         | 1.8 s  | 1.9 s  | 20 ms | 1.8 s       | 0.108   |

### 결론

**모든 핵심 경로가 Performance 95~98점으로 녹색 구간을 안정적으로 유지하며, 실사용 기준으로 충분한 성능을 보여줍니다.**

### 주요 지표 코멘트

- **`/` (홈)**: CLS 0으로 완벽, LCP 2.0s로 우수한 초기 로딩 속도
- **`/menu` (메뉴 리스트)**: 메뉴 썸네일이 많은 화면인데도 LCP 2.0s 유지, TBT 60ms로 메인 스레드 블로킹 거의 없음
- **`/order-history` (주문 내역)**: CLS 0.021로 미세한 레이아웃 이동만 존재 (실사용상 문제 없음)
- **`/admin` (관리자 대시보드)**: CLS 0.108로 카드 레이아웃이 많은 화면 특성상 상대적으로 높지만, 허용 범위 안이며 v1.0에서 카드/폰트 로딩 순서 조정으로 미세 개선 가능

## 5. 제약 사항 (Mock 모드 한계)

### USE_FIREBASE=false로 인한 한계

- **데이터 저장**: `localStorage`에만 저장되며, 브라우저를 닫거나 다른 기기에서 접속하면 데이터가 사라짐
- **기기 간 동기화 불가**: 모바일과 PC 간 주문 내역, 장바구니 등이 동기화되지 않음
- **실 주문/결제 불가**: 실제 주문 생성 및 결제 처리가 불가능함
- **푸시 알림 불가**: FCM(Firebase Cloud Messaging) 연동이 없어 푸시 알림을 받을 수 없음
- **실시간 업데이트 불가**: Firestore 실시간 리스너가 없어 주문 상태 변경 등을 실시간으로 확인할 수 없음

### 점주/사장님 안내 시 핵심 주의사항

**v0.9.1 Mock 버전은 데모/테스트 목적으로만 사용 가능하며, 실제 운영에는 사용할 수 없습니다.** 실제 주문/결제/푸시 알림 기능을 사용하려면 v1.0(Firebase 실연동) 버전으로 업그레이드해야 합니다. 현재 버전에서는 주문 내역, 장바구니 등이 브라우저를 닫으면 사라지며, 다른 기기와 데이터가 동기화되지 않습니다.
