### 4. 설정 페이지 접근 권한 문제 ✅

**오류**: "접근 권한이 필요합니다" 메시지 표시 (실제로는 권한 있음)

**원인**: `getCurrentUser()`가 `USE_FIREBASE`가 true일 때 null을 반환

**수정**:
- `getCurrentUser()` 대신 `useAuth()` 훅 사용
- `AuthContext`에서 사용자 정보를 가져오도록 변경

**파일**: `src/pages/admin/Settings/index.tsx`

```typescript
// 변경 전
import { getCurrentUser } from '../../../lib/auth';
const user = getCurrentUser();

// 변경 후
import { useAuth } from '../../../contexts/AuthContext';
const { user } = useAuth();
```

## 🔧 기술적 세부사항

### Firestore 구조

**컬렉션**: `stores/{storeId}`  
**문서 타입**: `StoreDoc` (기존 스키마 재사용)

**필드 구조**:
```typescript
{
  storeId: string;
  name: string;
  address: {
    full: string;
    detail: string;
    lat?: number;
    lng?: number;
  };
  phone: string;
  businessHours: {
    open: string;  // "10:00"
    close: string; // "22:00"
    days: string[]; // ["mon", "tue", ...]
  };
  isOpen: boolean;
  deliveryAvailable: boolean;
  minOrderAmount: number;
  deliveryFee: number;
  settings: {
    pointsRate: number;
    pointsMinUse: number;
  };
  createdAt: Timestamp;
  updatedAt: Timestamp;
}
```

### Firestore 직접 접근

별도 API 파일 없이 Firestore 헬퍼 함수를 직접 사용:
- `storeDocRef(STORE_ID)`: 문서 참조
- `getDoc()`: 읽기
- `setDoc(..., { merge: true })`: 쓰기 (병합)

**장점**:
- 코드 간결성
- 파일 수 감소
- 유지보수 용이

## 🔐 보안 및 검증

### 입력 검증
- 가게 이름: 필수, 공백 제거
- 전화번호: 필수, 공백 제거
- 주소: 필수, 공백 제거

### 권한 체크
- 관리자 설정: `ProtectedRoute`로 관리자/소유자만 접근
- 마이페이지: 모든 로그인 사용자 접근 가능

### Firestore Rules (권장)
```javascript
match /stores/{storeId} {
  allow read: if true; // 모두 읽기 가능
  allow write: if request.auth != null 
               && (request.auth.token.role == 'owner' 
                   || request.auth.token.role == 'admin');
}
```
