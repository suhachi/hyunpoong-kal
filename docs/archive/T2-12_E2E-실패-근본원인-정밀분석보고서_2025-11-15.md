## 1. Root Cause (한 줄 요약)

**Cart 컴포넌트의 `forceReload()` 호출이 `useEffect` 의존성 배열에 함수 자체를 포함하여 무한 루프를 유발하며, 실제로는 페이지 마운트 시점에 React state 업데이트가 비동기로 완료되기 전에 렌더링이 먼저 일어나 `items.length === 0` 조건으로 EmptyState가 렌더링되고 `#pickup` 요소가 DOM에 존재하지 않는 문제**

### C. 소스 코드 추적

#### C-1. `Cart.tsx` (라인 106-127)
```tsx
if (items.length === 0) {
  return (
    <div className="flex flex-col items-center justify-center min-h-[60vh] px-4">
      <div className="w-24 h-24 mb-6 rounded-full bg-[#2E1C10]/5 flex items-center justify-center">
        <ShoppingBag className="w-12 h-12 text-[#2E1C10]/40" />
      </div>
      <h2 className="text-xl text-[#2E1C10] mb-2">
        장바구니가 비어있어요
      </h2>
      ...
    </div>
  );
}
```

**문제점**: 
- `items.length === 0`이면 EmptyState만 렌더링하고 early return
- `#pickup` 라디오 버튼은 라인 162 이후에 있는 RadioGroup에 위치
- EmptyState가 렌더링되면 `#pickup`이 DOM에 존재하지 않음

#### C-2. `Cart.tsx` (라인 67-70) - forceReload 호출
```tsx
// Cart 페이지 마운트 시 localStorage에서 최신 상태 강제 로드
// SPA 네비게이션 시 CartContext state와 localStorage 동기화 보장
useEffect(() => {
  forceReload();
}, [forceReload]);
```

**치명적 문제**:
- `useEffect`의 의존성 배열에 `forceReload` 함수 자체를 포함
- `forceReload`는 `CartProvider` 내부에서 매 렌더마다 새로운 함수 인스턴스로 생성됨
- 이로 인해 `useEffect`가 무한 루프로 실행될 가능성이 매우 높음
- **의도**: Cart 마운트 시 한 번만 실행
- **실제**: `forceReload` 참조가 변경될 때마다 실행 → 무한 루프 또는 예측 불가능한 동작

#### C-3. `CartContext.tsx` (라인 199-212) - forceReload 구현
```tsx
const forceReload = () => {
  try {
    const stored = localStorage.getItem(STORAGE_KEY);
    if (stored) {
      const data = JSON.parse(stored);
      setItems(data.items || []);
      setDeliveryTypeState(data.deliveryType || 'delivery');
      setDeliveryAddressState(data.deliveryAddress);
      setRequestsState(data.requests || '');
      setCouponId(data.couponId);
      setCouponDiscount(data.couponDiscount || 0);
    }
  } catch (error) {
    console.error('Failed to force reload cart from localStorage:', error);
  }
};
```

**문제점**:
- `forceReload`가 Provider 함수 컴포넌트 내부에서 매 렌더마다 재생성됨
- `useCallback`으로 메모이제이션되지 않음
- 여러 개의 setState 호출이 연속으로 일어나 React 배치 업데이트가 제대로 작동하지 않을 수 있음

#### C-4. Race Condition 분석

**시나리오**:
```
T0: MenuDetail에서 addItem() 호출
T1: localStorage.setItem('hyunpung_cart', ...) 완료 ✅
T2: React state 업데이트 (비동기 배치)
T3: 토스트 표시
T4: 테스트가 page.goto('/cart') 실행
T5: Cart 컴포넌트 마운트
T6: useEffect(() => forceReload(), [forceReload]) 실행
T7: forceReload() 내부에서 6개의 setState 호출
T8: setState 배치 업데이트 대기 중...
T9: Cart 컴포넌트 첫 렌더링 시작 → items는 아직 빈 배열 []
T10: items.length === 0 조건 만족 → EmptyState 렌더링 ❌
T11: (이후 setState 완료되어도 이미 늦음)
```

**근본 원인**:
- `forceReload()`가 6개의 개별 `setState`를 연속 호출
- React 18의 자동 배칭이 있어도 `useEffect` 내부에서 실행되는 동기 코드와 첫 렌더링 사이의 타이밍 이슈
- `forceReload`가 `useEffect` 의존성 배열에 포함되어 예측 불가능한 재실행
- **Cart 컴포넌트가 마운트될 때 `items` state가 아직 업데이트되기 전에 렌더링**

#### C-5. localStorage vs React State 불일치

**localStorage 상태** (테스트 로그 확인):
```javascript
// 테스트 라인 128-132
const cartItems = await page.evaluate(() => {
  const data = localStorage.getItem('hyunpung_cart');
  return data ? JSON.parse(data).items : [];
});
console.log('장바구니 아이템 개수:', cartItems.length); // ✅ 1
```

**React State 상태** (Cart 컴포넌트):
```tsx
const { items } = useCart(); // ❌ [] (빈 배열)
```

**불일치 원인**:
- localStorage에는 정상적으로 저장됨
- CartContext의 초기 `useEffect([], [])` (라인 20-68)는 mount 시 한 번만 실행
- SPA에서 CartProvider는 최상위에 위치하여 unmount되지 않음
- MenuDetail → Cart 이동 시 CartProvider는 이미 마운트된 상태
- 따라서 초기 로드 useEffect가 재실행되지 않음
- `forceReload()` 호출이 의도대로 작동해야 하나, 위의 타이밍/의존성 문제로 실패

### D. 추가 이벤트 리스너 분석

`CartContext.tsx` (라인 42-63)에서 추가한 이벤트 리스너들:
```tsx
// storage event listener: 다른 탭이나 창에서 localStorage 변경 시 동기화
const handleStorageChange = (e: StorageEvent) => { ... }

// visibilitychange: 탭이 다시 활성화될 때 localStorage 재동기화
const handleVisibilityChange = () => { ... }

// focus: 창이 포커스를 받을 때 localStorage 재동기화
const handleFocus = () => { ... }
```

**문제점**:
- `storage` 이벤트는 **다른 탭/창**에서 localStorage 변경 시에만 트리거됨 (같은 탭 내에서는 작동하지 않음)
- `visibilitychange`와 `focus` 이벤트는 Playwright 환경에서 자동으로 트리거되지 않음
- 즉, 이 이벤트 리스너들은 테스트 시나리오에서 전혀 도움이 되지 않음

## 3. Failure Type 분류

### **B) 앱 코드 문제** (Primary)

**이유**:
- Cart 컴포넌트의 `useEffect` 의존성 배열에 메모이제이션되지 않은 함수를 포함 → 무한 루프 또는 예측 불가능한 동작
- `forceReload()` 함수가 `useCallback`으로 감싸지지 않아 매 렌더마다 새 인스턴스 생성
- `forceReload()` 내부에서 6개의 개별 `setState` 호출 → 비효율적이고 타이밍 이슈 유발
- SPA 환경에서 CartProvider가 unmount되지 않아 초기 로드 로직이 재실행되지 않는데, 이를 보완하는 메커니즘이 부족
- localStorage와 React state 동기화가 제대로 이루어지지 않음

### **A) 테스트 코드 문제** (Secondary)

**이유**:
- `expect(pickupRadio).toBeVisible({ timeout: 10000 })` - 10초는 충분히 긴 시간이나, 실제로는 state 업데이트가 완료되기를 기다리는 메커니즘이 없음
- `page.goto('/cart')` 직후 바로 `#pickup` 체크 → Cart 컴포넌트의 state hydration을 기다리지 않음
- localStorage 검증은 하지만, React state 동기화를 기다리는 로직 없음
- 테스트가 "localStorage에 있으면 UI에도 반영될 것"이라고 낙관적으로 가정

### **분류 결론: A + B (복합)**

테스트와 앱 코드 모두에 문제가 있으나, **앱 코드의 근본적인 아키텍처 문제가 주 원인**이며, 테스트는 이를 제대로 방어하지 못함.

## 6. 최종 요약

### 왜 `expect(pickupRadio).toBeVisible()`이 10초 동안 기다려도 실패했는가?

**직접 원인**: Cart 컴포넌트의 `items` state가 비어있어 `items.length === 0` 조건에 의해 EmptyState만 렌더링되고, `#pickup` 라디오 버튼이 포함된 RadioGroup이 DOM에 존재하지 않았기 때문.

**근본 원인**: 
1. `forceReload()` 함수가 `useCallback`으로 메모이제이션되지 않아 `useEffect` 의존성 배열에서 무한 루프 또는 예측 불가능한 재실행 유발
2. `forceReload()` 내부의 6개 개별 `setState` 호출이 비동기 배치 업데이트와 첫 렌더링 사이의 타이밍 이슈 발생
3. SPA 환경에서 CartProvider가 unmount되지 않아 초기 로드 로직이 재실행되지 않는데, 추가한 이벤트 리스너들(storage, visibilitychange, focus)이 테스트 환경에서 트리거되지 않음
4. localStorage에는 데이터가 있지만 React state와 동기화되지 않은 채로 Cart 컴포넌트가 렌더링됨

### 이게 테스트 잘못인지, 실제 앱 버그인지, 둘 다인지?

**둘 다 (A + B)**

- **앱 코드 버그 (Primary)**: CartContext의 state 동기화 로직이 SPA 환경에서 제대로 작동하지 않음. `forceReload` 구현 방식이 근본적으로 잘못됨.
- **테스트 코드 문제 (Secondary)**: localStorage 검증만 하고 React state 동기화를 기다리지 않음. 너무 낙관적인 가정.

### 어디를 어떻게 고쳐야 재발하지 않는가?

**필수 수정**:
1. `CartContext.tsx`: `forceReload`를 `useCallback`으로 감싸기
2. `Cart.tsx`: `useEffect` 의존성 배열을 `[]`로 수정하거나, `forceReload`가 메모이제이션되었다면 `[forceReload]` 유지
3. `CartContext.tsx`: 6개 setState를 `useReducer`로 통합하여 단일 업데이트로 최적화

**권장 수정**:
4. `order-flow.spec.ts`: `page.goto('/cart')` 후 `waitForFunction`으로 UI 렌더링 대기
5. Cart 컴포넌트: `isHydrated` 플래그 추가하여 로딩 상태 관리
6. 테스트용 `data-testid` 속성 추가

**아키텍처 개선 (장기)**:
7. CartContext를 `useReducer` + `context` 패턴으로 리팩토링
8. localStorage 동기화를 커스텀 훅(`useLocalStorage`)으로 분리하여 재사용성 향상
