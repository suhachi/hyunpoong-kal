## 2. 원인 분석

### 2.1. 코드 구조 비교

**성공한 함수들 (`onReviewCreatedV1`, `onScheduleExpirePoints`, `onScheduleExpireCoupons`)**:
```typescript
export const onReviewCreatedV1 = functions
  .region(REGION)
  .runWith(RUNTIME_OPTS)
  .firestore.document('stores/{storeId}/reviews/{reviewId}')
  .onCreate(async (snap, context) => { ... });
```

**실패한 함수 (`onOrderStatusChanged`)**:
```typescript
export const onOrderStatusChanged = functions
  .region(REGION)
  .runWith(RUNTIME_OPTS)
  .firestore.document('stores/{storeId}/orders/{orderId}')
  .onUpdate(async (change, context) => { ... });
```

### 2.2. 발견된 문제점

1. **타입 안전성 부족**
   - `prevStatus`, `nextStatus`에 타입 단언 없이 사용
   - `finalAmount` 체크가 `!finalAmount`로 되어 있어 `0` 값도 거부할 수 있음

2. **환불 로직 미완성**
   - 주문 취소 시 환불 로직이 TODO 주석으로만 남아있음
   - 실제 환불 처리가 없어 데이터 일관성 문제 가능

3. **에러 처리 개선 필요**
   - 환불 실패 시에도 계속 진행하도록 try-catch 추가 필요

### 2.3. 배포 실패 가능 원인

코드 구조 자체는 성공한 함수들과 동일하므로, 배포 실패 원인은:
- **타입 체크 실패**: TypeScript 컴파일은 성공했지만 런타임에서 타입 불일치 가능
- **환불 로직 미완성**: 배포 시 검증 단계에서 로직 완성도 체크 가능성
- **Firebase Functions 배포 검증**: 내부 검증 로직에서 문제 감지 가능

## 3. 수정 내용

### 3.1. 타입 안전성 개선

**수정 전**:
```typescript
const prevStatus = before.status;
const nextStatus = after.status;
const finalAmount = after.finalAmount as number | undefined;

if (!userId || !finalAmount) {
  // finalAmount가 0일 때도 거부됨
}
```

**수정 후**:
```typescript
const prevStatus = before.status as string | undefined;
const nextStatus = after.status as string | undefined;
const finalAmount = after.finalAmount as number | undefined;

if (!userId || finalAmount === undefined) {
  // finalAmount가 0일 때는 허용
}
```

### 3.2. 환불 로직 구현

**수정 전**:
```typescript
if (nextStatus === 'cancelled' && prevStatus !== 'cancelled') {
  // TODO: 환불 정책에 따라 환불 포인트 계산
  console.log('[onOrderStatusChanged] Order cancelled (refund logic TODO)', { userId, orderId });
}
```

**수정 후**:
```typescript
if (nextStatus === 'cancelled' && prevStatus !== 'cancelled') {
  // 주문 완료 상태였다면 적립된 포인트 환불
  if (prevStatus === 'completed') {
    const earnedAmount = Math.floor(finalAmount * POINTS_POLICY.ORDER_REWARD_RATE);
    if (earnedAmount > 0) {
      try {
        await refundPointsServer({
          userId,
          storeId,
          amount: earnedAmount,
          refKind: 'order',
          refId: orderId,
          note: '주문 취소 환불',
        });
        console.log('[onOrderStatusChanged] Refunded points for cancelled order', { userId, orderId, amount: earnedAmount });
      } catch (refundError) {
        console.error('[onOrderStatusChanged] Failed to refund points:', refundError);
      }
    }
  }
  console.log('[onOrderStatusChanged] Order cancelled', { userId, orderId });
}
```

### 3.3. 에러 처리 개선

- 환불 로직에 독립적인 try-catch 추가
- 환불 실패 시에도 함수가 정상 종료되도록 처리
