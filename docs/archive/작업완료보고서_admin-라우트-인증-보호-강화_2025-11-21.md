## 📋 문제 상황

### 발견된 문제

1. **`/admin/dashboard` 진입 실패**
   - `/admin/dashboard` 경로로 직접 접근 시 진입 불가
   - URL은 변경되지만 실제 화면은 표시되지 않음

2. **인증 보호 불일치**
   - `/admin/dashboard`는 로그인 화면 표시됨 (정상)
   - 다른 `/admin/*` 경로들(`/admin/menus`, `/admin/orders` 등)은 로그인 없이 접근 가능 (문제)
   - `/admin`은 대시보드로 바로 진입됨 (문제)

3. **보안 취약점**
   - 관리자 페이지들이 인증 없이 접근 가능한 상태
   - 모든 `/admin/*` 경로가 동일하게 보호되어야 하는데 일부만 보호됨

---

## 🔍 원인 분석

### 핵심 원인

**React Router의 중첩 라우팅에서 `ProtectedRoute`가 자식 라우트까지 완전히 보호하지 못함**

#### 라우팅 구조
```tsx
<Route path="/admin" element={<ProtectedRoute><AdminLayout /></ProtectedRoute>}>
  <Route index element={<Dashboard />} />
  <Route path="dashboard" element={<Dashboard />} />
  <Route path="menus" element={<AdminMenus />} />
  <Route path="orders" element={<AdminOrders />} />
  ...
</Route>
```

**문제점**:
1. `ProtectedRoute`가 부모 라우트(`/admin`)의 `element`에만 적용됨
2. 자식 라우트들(`/admin/menus`, `/admin/orders` 등)이 직접 접근될 때 `ProtectedRoute`가 완전히 작동하지 않을 수 있음
3. `AdminLayout`이 렌더링된 후 `<Outlet />`을 통해 자식 라우트가 렌더링되는데, 이 시점에 인증 체크가 누락될 수 있음

---

## ✅ 해결 방법

### 1. `/admin/dashboard` 명시 라우트 추가

**파일**: `src/App.tsx`

**변경 내용**:
```tsx
{/* 대시보드 */}
<Route index element={<Dashboard />} />
<Route path="dashboard" element={<Dashboard />} />  // ← 추가
```

**효과**: `/admin/dashboard` 경로로 직접 접근 가능하도록 명시적 라우트 추가

---

### 2. ProtectedRoute 로그 강화

**파일**: `src/components/shared/ProtectedRoute.tsx`

**변경 내용**:
- `console.log` → `console.warn`으로 변경 (더 눈에 띄게)
- 리다이렉트 전 상세 로그 추가:
  - 원래 접근하려던 경로 출력
  - 리다이렉트 이유 명시

**효과**: 디버깅 시 문제 추적 용이

---

### 3. AdminLayout에서 이중 인증 체크 추가

**파일**: `src/pages/admin/_layout/AdminLayout.tsx`

**변경 내용**:
```tsx
import { useState, useEffect } from 'react';
import { Outlet, NavLink, useNavigate, useLocation } from 'react-router-dom';

export function AdminLayout() {
  const navigate = useNavigate();
  const location = useLocation();  // ← 추가
  const { user, loading } = useAuth();
  
  // useEffect로 user 상태 모니터링
  useEffect(() => {
    if (!loading && !user) {
      console.warn('🔒 AdminLayout: ❌ No user, redirecting to /login');
      console.warn('🔒 AdminLayout: 원래 접근하려던 경로:', location.pathname);
      navigate('/login', { replace: true, state: { from: location } });
    }
  }, [user, loading, location, navigate]);

  // user가 없으면 로그인 페이지로 리다이렉트
  if (!user) {
    return (
      <div>로그인이 필요합니다. 로그인 페이지로 이동합니다...</div>
    );
  }
  
  // 정상 렌더링
  return <div>...</div>;
}
```

**핵심 로직**:
1. **useEffect로 user 상태 모니터링**: `user`가 없으면 자동으로 `/login`으로 리다이렉트
2. **조건부 렌더링**: `user`가 없으면 리다이렉트 중임을 표시
3. **이중 보호**: `ProtectedRoute` + `AdminLayout` 모두에서 인증 체크

**효과**: 
- 모든 `/admin/*` 경로가 동일하게 보호됨
- 자식 라우트가 직접 접근되어도 인증 체크 보장
- 보안 취약점 제거

## 🎯 동작 방식

### 모든 `/admin/*` 경로 보호 흐름

1. **사용자가 `/admin/*` 경로 접근**
   ```
   /admin/dashboard
   /admin/menus
   /admin/orders
   등등...
   ```

2. **ProtectedRoute 인증 체크**
   - `user`가 없으면 → `/login`으로 리다이렉트
   - `user`가 있지만 `role`이 `owner` 또는 `admin`이 아니면 → `/`로 리다이렉트
   - 인증 통과 시 → `AdminLayout` 렌더링

3. **AdminLayout 추가 인증 체크**
   - `useEffect`로 `user` 상태 모니터링
   - `user`가 없으면 → `/login`으로 리다이렉트 (이중 보호)
   - 인증 통과 시 → 자식 라우트 렌더링 (`<Outlet />`)

4. **자식 라우트 렌더링**
   - `Dashboard`, `AdminMenus`, `AdminOrders` 등 정상 렌더링
