# 문제 분석 보고서: 관리자 대시보드 접근 실패 원인

**작성일**: 2025-11-22  
**문제**: 관리자 계정(`admin@hyunpoongkalguksu.com`)으로 로그인했으나 관리자 대시보드(`/admin/dashboard`) 접근 불가  
**상태**: ✅ 해결 완료

## 📋 문제 요약

### 증상
- 사용자: `admin@hyunpoongkalguksu.com`
- 역할 표시: "고객" (Customer)
- 접근 시도: `/admin/dashboard`
- 결과: 접근 거부, 홈 페이지로 리다이렉트

### 기대 동작
- 역할: "관리자" 또는 "사장" (owner/admin)
- 관리자 대시보드 정상 접근 가능

## 🔍 근본 원인 분석

### 1. Mock 모드 vs Firebase 모드의 역할 처리 차이

#### Mock 모드 (`USE_FIREBASE=false`)

**코드 위치**: `src/contexts/AuthContext.tsx:48-62`

```typescript
const MOCK_USERS = {
  'admin@hyunpoongkalguksu.com': {
    uid: 'admin-001',
    email: 'admin@hyunpoongkalguksu.com',
    displayName: '관리자',
    role: 'owner' as UserRole,  // ✅ 명시적으로 'owner' 설정
    storeId: 'store-hyunpung',
  },
  // ...
};
```

**동작 방식**:
- `localStorage`에 저장된 Mock 사용자 데이터 사용
- `MOCK_USERS` 객체에서 이메일로 직접 조회
- **역할이 하드코딩되어 있어 항상 정확함**

#### Firebase 모드 (`USE_FIREBASE=true`)

**코드 위치**: `src/lib/auth/resolveUser.ts:22-45`

```typescript
export async function resolveUserFromFirebaseUser(firebaseUser: FirebaseUser): Promise<AuthUser> {
  const userDoc = await getDoc(doc(db, 'users', firebaseUser.uid));
  const userData = userDoc.data() as any | undefined;

  const role = (userData?.role as AuthUser['role']) || 'customer';  // ❌ 문제 지점
  // ...
}
```

**동작 방식**:
- Firestore의 `users/{userId}` 문서에서 사용자 정보 조회
- `role` 필드가 없거나 `null`이면 **기본값 `'customer'`로 설정**
- **관리자 이메일 여부를 확인하지 않음**

### 2. 문제 발생 시나리오

#### 시나리오 A: Firestore에 사용자 문서가 없는 경우

1. 사용자가 Firebase Auth로 로그인 성공
2. `resolveUserFromFirebaseUser` 호출
3. Firestore `users/{userId}` 문서 조회 → **문서 없음**
4. `userData?.role` = `undefined`
5. 기본값 `'customer'` 적용 ❌
6. 결과: 관리자 계정이 고객 역할로 설정됨

#### 시나리오 B: Firestore에 사용자 문서가 있지만 role 필드가 없는 경우

1. 사용자가 Firebase Auth로 로그인 성공
2. `resolveUserFromFirebaseUser` 호출
3. Firestore `users/{userId}` 문서 조회 → **문서 존재, 하지만 `role` 필드 없음**
4. `userData?.role` = `undefined`
5. 기본값 `'customer'` 적용 ❌
6. 결과: 관리자 계정이 고객 역할로 설정됨

#### 시나리오 C: Firestore에 role 필드가 'customer'로 잘못 설정된 경우

1. 사용자가 Firebase Auth로 로그인 성공
2. `resolveUserFromFirebaseUser` 호출
3. Firestore `users/{userId}` 문서 조회 → **`role: 'customer'`로 설정됨**
4. `userData?.role` = `'customer'`
5. `'customer'` 역할 적용 ❌
6. 결과: 관리자 계정이 고객 역할로 설정됨

### 3. 코드 흐름 분석

#### 로그인 프로세스 (Firebase 모드)

```
1. 사용자 로그인
   ↓
2. AuthContext.signIn() 호출
   ↓
3. Firebase Auth 인증 성공
   ↓
4. resolveUser(firebaseUser) 호출
   ↓
5. resolveUserFromFirebaseUser() 실행
   ↓
6. Firestore users/{userId} 문서 조회
   ↓
7. role 필드 확인
   ├─ role 있음 → 해당 role 사용
   └─ role 없음 → 'customer' 기본값 사용 ❌
   ↓
8. AuthUser 객체 생성
   ↓
9. ProtectedRoute 역할 체크
   ├─ role이 'owner' 또는 'admin' → 접근 허용 ✅
   └─ role이 'customer' → 접근 거부, 홈으로 리다이렉트 ❌
```

#### ProtectedRoute 동작

**코드 위치**: `src/components/shared/ProtectedRoute.tsx:54-58`

```typescript
// 특정 역할이 필요한데 권한이 없는 경우
if (roles && user && !roles.includes(user.role)) {
  console.log('🔒 ProtectedRoute: ⚠️ Insufficient role, redirecting to /');
  return <Navigate to="/" replace />;
}
```

**동작**:
- `/admin` 경로는 `roles={["owner", "admin"]}` 필요
- 사용자 역할이 `'customer'`이면 접근 거부
- 홈 페이지(`/`)로 리다이렉트

|------|---------------|--------|
| **Mock 모드** | `MOCK_USERS` 객체에서 하드코딩된 역할 사용 | ✅ 정확함 |

### 2. 기본값 설정의 문제

```typescript
// 문제 코드
const role = (userData?.role as AuthUser['role']) || 'customer';
```

**문제점**:
- Firestore에 `role` 필드가 없으면 무조건 `'customer'`로 설정
- 관리자 이메일 주소를 확인하지 않음
- Mock 모드와의 일관성 부족

### 3. 데이터 마이그레이션 누락

- Firebase 모드로 전환 시 기존 사용자 데이터에 `role` 필드가 없을 수 있음
- 관리자 계정의 Firestore 문서에 `role` 필드가 설정되지 않았을 가능성

### 4. 개발 환경과 프로덕션 환경의 차이

- **개발 환경**: Mock 모드 사용 → 역할 정상 작동
- **프로덕션 환경**: Firebase 모드 사용 → Firestore 데이터 의존적

## 🔄 향후 개선 사항

### 1. Firestore 데이터 마이그레이션

**권장 사항**:
- 기존 사용자 데이터에 `role` 필드 추가
- 관리자 계정의 Firestore 문서에 명시적으로 `role: 'owner'` 설정

**마이그레이션 스크립트 예시**:
```typescript
// Firebase Console 또는 Cloud Functions에서 실행
const adminEmails = ['admin@hyunpoongkalguksu.com'];

// 모든 사용자 문서 조회
const usersSnapshot = await db.collection('users').get();

for (const userDoc of usersSnapshot.docs) {
  const userData = userDoc.data();
  const email = userData.email;
  
  // role 필드가 없고 관리자 이메일인 경우
  if (!userData.role && adminEmails.includes(email)) {
    await userDoc.ref.update({ role: 'owner' });
  }
}
```

### 2. 역할 관리 개선

**현재 문제점**:
- 관리자 이메일이 코드에 하드코딩되어 있음
- 새로운 관리자 추가 시 코드 수정 필요

**개선 방안**:
- Firestore에 `adminEmails` 컬렉션 또는 설정 문서 생성
- 또는 Firebase Auth Custom Claims 사용

**예시 (Custom Claims)**:
```typescript
// Cloud Functions에서 실행
await admin.auth().setCustomUserClaims(uid, { role: 'owner' });

// 클라이언트에서 사용
const idTokenResult = await firebaseUser.getIdTokenResult();
const role = idTokenResult.claims.role || 'customer';
```
