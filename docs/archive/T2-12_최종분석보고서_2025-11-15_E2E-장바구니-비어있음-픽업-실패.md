## 1. 증상 및 흐름

- 두 테스트 모두 `#pickup` 라디오가 보이지 않아 실패
- localStorage에는 아이템이 정상적으로 담김 (테스트 로그: `장바구니 아이템 개수: 1`)
- Cart 컴포넌트는 `items.length === 0`일 때만 "장바구니가 비어있어요" 렌더링
- 테스트에서 페이지 이동 직후 UI가 비어있게 보임 → 상태 동기화 타이밍 문제 가능성

---

## 2. 코드 흐름 및 원인 분석

### 2.1 CartContext
- localStorage와 React 상태를 동기화
- addItem() 호출 시 localStorage에 아이템 저장, React 상태도 변경

### 2.2 MenuDetail
- 메뉴 상세에서 addItem() 호출
- localStorage에는 아이템이 담기지만, Cart의 items 상태가 즉시 반영되지 않을 수 있음

### 2.3 Cart
- items.length === 0이면 "장바구니가 비어있어요"만 렌더링
- 상태 동기화가 늦으면 UI가 비어있게 보임

### 2.4 E2E 테스트
- "담기" 클릭 후 바로 /cart로 이동 → React 상태가 아직 반영되지 않아 UI가 비어있음
- localStorage에는 아이템이 있으나, UI 렌더링은 race condition 발생

---

## 3. Playwright Best Practice 위반/개선점

- 상태 동기화 미보장: localStorage에 아이템이 담겨도, React 상태가 즉시 반영되지 않을 수 있음
- 페이지 이동 직후 UI 검증은 race condition을 유발
- 해결: `await page.waitForFunction(() => document.querySelector('#pickup'))` 등으로 UI와 상태 동기화 보장
- 셀렉터의 구체성 부족: 메뉴 카드 클릭 시, 구체적인 셀렉터(`a[href^="/menu/menu-"]`) 사용 권장
- 중간 상태 검증 누락: "담기" 버튼 클릭 후 localStorage와 UI 모두 검증 필요
- Mock 세션/컨텍스트 관리: 관리자 컨텍스트 분리, 세션 주입 후 페이지 reload로 상태 보장 필요

## 4. 개선방안 및 코드 스니펫

### 4.1 상태 동기화 보장
```typescript
// 담기 버튼 클릭 후, 장바구니 페이지 이동 전 UI 동기화 대기
await addToCartButton.click();
await expect(page.getByText(/장바구니에 담았습니다/)).toBeVisible();
await page.waitForFunction(() => {
  return !!document.querySelector('#pickup');
}, { timeout: 5000 });
await page.goto('/cart');
await expect(page.locator('#pickup')).toBeVisible({ timeout: 10000 });
```

### 4.2 관리자 컨텍스트 동기화
```typescript
// 관리자 페이지 진입 후 reload로 상태 보장
await adminPage.goto('/admin/orders');
await adminPage.reload();
await expect(adminPage.getByText(/주문 관리|주문 현황|Orders/i)).toBeVisible({ timeout: 10000 });
```
