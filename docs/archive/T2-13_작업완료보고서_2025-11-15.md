## 3. 오늘 적용한 주요 변경사항
### 3.1 `order-flow.spec.ts`
- 이전: `page.waitForFunction` 으로 bodyText에서 '로딩 중...' 또는 '장바구니가 비어있어요' 문구 제거를 폴링 → 30s 타임아웃 발생.
- 현재: 직접 `page.locator('#pickup')` / `#delivery` 가시성 대기(`toBeVisible({ timeout: 15000 })`).
- 추가: `page.goto('/cart', { waitUntil: 'domcontentloaded' })` + `page.waitForLoadState('networkidle')` 로 초기 마운트 안정화 시도.

### 3.2 Cart 관련 기존 구조(참고)
- `CartContext.forceReload()` 로 localStorage → state 재동기화.
- `Cart.tsx` 에서 `isHydrating` 플래그로 초기 렌더 로딩 처리 (double setTimeout → 현재 유지).

## 5. 원인 가설 (우선순위 순)
1. Mock 모드에서 초기 Cart 렌더 직후 localStorage 읽기 순서가 React 마운트 타이밍과 어긋나 Playwright가 빠르게 DOM 질의 → 아직 라디오 영역 조건 분기 미도달.
2. test 환경에서 CPU throttling 또는 워커 초기화로 첫 렌더 전환 지연.
3. `isHydrating` 타이밍이 실제 라디오 표시 결정 분기보다 늦게 false 되는 케이스 발생 (조건 분기: `items.length === 0` → EmptyState → 이후 업데이트 누락).
4. LocalStorage 직렬화/역직렬화 시 테스트 런너 sandbox 차이로 직후 state 배치 처리 지연.
5. React 18 자동 배치 + 두 번의 setTimeout 조합이 테스트 환경에서 순서를 예측 불가능하게 만듦.

## 7. 개선 옵션 후보 (내일 판단)
- (A) `CartContext` 초기화 시 `useLayoutEffect` 활용하여 첫 렌더 전에 localStorage 반영 (SSR 영향 없으므로 후보).
- (B) `Cart.tsx`에서 초기 마운트 시 별도 `prefetchItems()` 호출 → items 배열을 바로 Hydrate 후 `isHydrating` false 처리.
- (C) 테스트 전용 헬퍼: `/cart?e2e=1` 쿼리 처리하여 강제 동기화 루틴 (테스트 격리).
- (D) React 18 StrictMode 여부 점검(이중 마운트로 타이밍 이슈 유발 가능) 후 필요 시 테스트 빌드에서 해제.
