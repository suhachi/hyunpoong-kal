# Phase 1 – 관리자 종합 완료 보고서 (2025-11-14)

## 1. 개요

Phase 1은 관리자/고객 기본 구조 안정화를 목표로, 인증 시스템 통일(T1-1), Firebase/Mock 환경 스위치 안정화(T1-3), 관리자 11개 라우트 렌더링 검증(T2-1), Settings 5개 탭 안정성 보강(T2-2), 주요 화면 10개 Null Guard 적용(T2-3), Playwright 기반 E2E 자동화 구축(T2-4)을 완료했다. React 18/Vite 기반 프론트엔드에서 Firebase Firestore/Auth/Functions와 Mock 모드를 환경변수(`USE_FIREBASE`)로 전환 가능하도록 설계했으며, Playwright를 통해 관리자 진입/사이드바 네비게이션/Settings 렌더링 등 18개 자동화 테스트를 구축했다. Phase 1 완료 시점에서 관리자 화면의 기본 라우팅/렌더링/가드는 안정화되었으며, 실제 주문 플로우/FCM 알림/Settings Firebase 저장 등은 Phase 2에서 진행할 예정이다.

## 2. 작업별 요약 (T1-1, T1-3, T2-1~T2-4)

### 2.1 T1-1 – AuthContext 통일

**문제**: 관리자 페이지 진입 시 `AuthContext`는 `localStorage.getItem('mockUser')`를 사용하고, `getCurrentUser()`는 `localStorage.getItem('mockRole')`을 사용하여 인증 정보 불일치로 진입 불가 발생.

**해결**: `AuthContext`를 단일 진실의 원천(Single Source of Truth)으로 통일. `src/lib/auth.ts`의 `getCurrentUser()`, `mockLogin()`, `mockLogout()` 함수를 모두 `mockUser` 키만 사용하도록 수정하고, `AdminLayout.tsx`에서 `getCurrentUser()` 대신 `useAuth()` 훅 사용으로 전환.

**영향**: 관리자/고객 라우팅 안정성 확보, 로그인 상태 판단 명확화, `mockRole` 키 제거로 데이터 동기화 문제 원천 차단.

**관련 파일**:
- `src/lib/auth.ts` (getCurrentUser/mockLogin/mockLogout)
- `src/contexts/AuthContext.tsx`
- `src/pages/admin/_layout/AdminLayout.tsx`

### 2.2 T1-3 – Firebase/Mock 스위치 안정화

**스위치 방식**: `src/config/env.ts`에서 `export const USE_FIREBASE = false;` 하드코딩. 환경변수(`VITE_USE_FIREBASE`)가 존재하면 파싱하도록 설계했으나, Phase 1에서는 Mock 모드 고정으로 개발/테스트 진행.

**개발/테스트 패턴**:
- 로컬 개발: Mock 모드 (USE_FIREBASE=false)
- 관리자 플로우: `/dev` 페이지에서 Mock 사용자 선택 후 진입
- E2E 테스트: Playwright에서 Mock 사용자 localStorage 주입

**주의사항**: Mock 모드에서는 Firestore/Auth/Functions 호출이 모두 무시되고, `src/contexts/AuthContext.tsx` 내 MOCK_USERS 객체 기반으로 동작. Firebase ON 전환 시 실제 Firestore rules, Auth providers, Functions 배포 필수.

**관련 파일**:
- `src/config/env.ts`
- `src/lib/firebase.ts`
- `src/contexts/AuthContext.tsx`
- `.env.example` (VITE_USE_FIREBASE 주석)
