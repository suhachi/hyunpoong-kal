## 📋 작업 개요

모바일 성능 최적화 작업의 두 번째 단계로, **코드 스플리팅**을 통해 초기 번들 크기를 대폭 감소시켰습니다. 특히 고객이 자주 사용하는 경로(`/`, `/menu`, `/order-history`)에서 Admin 영역(`/admin/**`)과 차트/관제 코드(recharts 등)를 완전히 분리하여, 고객이 관리자 화면을 사용하지 않으면 해당 코드를 로드하지 않도록 구현했습니다.

## 🎯 이 작업으로 기대할 수 있는 효과

### 1. 초기 로딩 속도 대폭 개선

**효과:**
- ✅ **초기 번들 크기 58% 감소**
  - 이전: 1.62 MB (단일 파일)
  - 현재: 679.77 KB (메인 번들)
  - **약 940KB 감소** → 모바일 네트워크에서 약 2-3초 단축

- ✅ **First Contentful Paint (FCP) 개선 예상**
  - 초기 다운로드 시간 단축
  - 파싱 및 실행 시간 단축
  - 목표: FCP < 1.8초 달성 가능성 증가

- ✅ **Time to Interactive (TTI) 개선 예상**
  - JavaScript 실행 시간 단축
  - 메인 스레드 블로킹 시간 감소

### 3. 라우트 단위 코드 스플리팅

**파일:** `src/App.tsx`

#### 변경 내용:

1. **React.lazy + Suspense 적용**
   - 모든 페이지 컴포넌트를 `React.lazy()`로 변경
   - `Suspense`로 Routes 래핑
   - 로딩 폴백 컴포넌트 추가

2. **고객 앱 페이지 lazy-load**
   ```tsx
   const Home = lazy(() => import('./pages/app/Home').then(m => ({ default: m.Home })));
   const MenuList = lazy(() => import('./pages/app/MenuList').then(m => ({ default: m.MenuList })));
   const OrderHistory = lazy(() => import('./pages/app/OrderHistory').then(m => ({ default: m.OrderHistory })));
   // ... 총 16개 페이지
   ```

3. **관리자 페이지 lazy-load**
   ```tsx
   const Dashboard = lazy(() => import('./pages/admin/Dashboard').then(m => ({ default: m.Dashboard })));
   const AdminOrders = lazy(() => import('./pages/admin/Orders').then(m => ({ default: m.AdminOrders })));
   const AdminAnalytics = lazy(() => import('./pages/admin/Analytics').then(m => ({ default: m.AdminAnalytics })));
   // ... 총 12개 페이지
   ```

4. **Suspense 래핑**
   ```tsx
   <Suspense fallback={<LoadingFallback />}>
     <Routes>
       {/* 모든 라우트 */}
     </Routes>
   </Suspense>
   ```

#### 결과:
- ✅ 모든 페이지가 개별 청크로 분리
- ✅ Admin 페이지는 별도 청크로 분리
- ✅ 고객 앱 진입 시 Admin 코드 미로드
