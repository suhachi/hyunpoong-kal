## 📋 작업 개요

모바일 성능 최적화 작업의 세 번째 단계로, 고객이 자주 사용하는 화면(홈, 메뉴 리스트/상세, 장바구니)의 **이미지 로딩과 리스트 렌더링을 최적화**하여 모바일 체감 속도를 개선했습니다. ATOMIC 원칙에 따라 작은 단위로 나눠서 진행했으며, 각 단계마다 빌드 및 검증을 수행했습니다.

## 🎯 이 작업으로 기대할 수 있는 효과

### 1. 이미지 로딩 성능 개선

**효과:**
- ✅ **초기 로딩 시간 단축**
  - 뷰포트에 보이지 않는 이미지는 즉시 로드하지 않음
  - 초기 HTML 파싱 및 렌더링 시간 단축
  - 목표: LCP (Largest Contentful Paint) < 2.5초 달성 가능성 증가

- ✅ **네트워크 사용량 감소**
  - 사용자가 실제로 보는 이미지만 로드
  - 스크롤하지 않는 이미지는 로드하지 않음
  - 모바일 데이터 사용량 감소 (평균 30-50% 절감 예상)

- ✅ **메모리 사용량 최적화**
  - 필요한 이미지만 메모리에 로드
  - 브라우저 메모리 효율 향상
  - 저사양 기기에서도 부드러운 동작

### 2. 렌더링 성능 개선

**효과:**
- ✅ **불필요한 리렌더링 방지**
  - React.memo로 카드 컴포넌트 최적화
  - 부모 컴포넌트 리렌더링 시 자식 컴포넌트 불필요한 재렌더링 방지
  - 목표: TBT (Total Blocking Time) < 200ms 달성 가능성 증가

- ✅ **함수 재생성 방지**
  - useCallback으로 핸들러 함수 메모이제이션
  - props 변경 최소화로 memo 효과 극대화
  - 리스트 스크롤 시 성능 향상

- ✅ **스크롤 성능 개선**
  - 리스트 아이템 렌더링 최적화
  - 프레임 드랍 감소
  - 부드러운 스크롤 경험

### 3. 사용자 경험 개선

**효과:**
- ✅ **빠른 첫 화면 표시**

## ⚠️ 주의 사항

1. **Placeholder 이미지 경로**
   - 현재 `DEFAULT_MENU_IMAGE = '/images/placeholder-menu.png'`로 설정
   - 실제 이미지 파일이 준비되면 경로 업데이트 필요
   - 또는 실제 placeholder 이미지 파일 추가 필요

2. **이미지 로딩 순서**
   - lazy loading으로 인해 스크롤 시 이미지가 로드됨
   - 사용자가 빠르게 스크롤하면 이미지가 늦게 표시될 수 있음
   - 필요 시 `loading="eager"`로 중요한 이미지만 즉시 로드 가능

3. **브라우저 호환성**
   - `loading="lazy"`는 최신 브라우저에서 지원
   - 구형 브라우저에서는 폴백 동작 (정상 로드)
   - `decoding="async"`는 대부분의 브라우저에서 지원
