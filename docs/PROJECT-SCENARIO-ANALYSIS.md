## 1. 🍜 고객(User) 시나리오 분석

고객이 앱에 진입하여 주문을 완료하고 리뷰를 남기기까지의 여정을 코드 기반으로 정밀 분석했습니다.

### 1.1 진입 및 탐색 (Entry & Discovery)
*   **진입점 (`/`)**:
    *   `AppLayout`을 통해 하단 네비게이션 바가 있는 화면으로 진입합니다.
    *   **비로그인 상태**에서도 메뉴 조회 및 장바구니 담기가 가능합니다 (Guest 접근 허용).
    *   **FCM 토큰**: 앱 실행 시 `ensureFcmToken()`이 호출되어 푸시 알림 권한을 요청하고 토큰을 확보합니다.
*   **홈 화면 (`Home.tsx`)**:
    *   **영업 상태 확인**: 영업 중 여부와 시간(10:00 - 22:00)이 표시됩니다.
    *   **추천 메뉴**: 'best' 뱃지가 달린 메뉴 상위 2개가 노출됩니다.
    *   **빠른 접근**: 포인트 현황, 내 쿠폰함으로 바로 이동하는 퀵 메뉴가 있습니다.
*   **메뉴 상세 (`MenuDetail.tsx`)**:
    *   URL 파라미터 `menuId`로 메뉴 정보를 로드합니다.
    *   **옵션 선택**: 필수/선택 옵션이 구분되어 있으며, 필수 옵션 미선택 시 장바구니 담기가 차단됩니다.
    *   **장바구니 담기**: `useCart().addItem()`을 통해 로컬 스토리지 또는 메모리에 상품을 저장합니다. 성공 시 장바구니 탭 뱃지 카운트가 증가합니다.

### 1.2 장바구니 및 주문 준비 (Cart & Checkout)
*   **장바구니 (`Cart.tsx`)**:
    *   담은 메뉴의 수량을 조절하거나 삭제할 수 있습니다.
    *   **배달/포장 선택**: 상단 탭에서 수령 방식을 선택합니다. '배달' 선택 시 주소 설정이 필요합니다.
    *   **주문하기 버튼**: 최소 주문 금액 검증 후 `checkout` 페이지로 이동합니다.
*   **주문서 작성 (`Checkout.tsx`)**:
    *   **인증 체크**: 비로그인 상태라면 `/login`으로 리다이렉트됩니다.
    *   **정보 입력**:
        *   전화번호: 필수 입력 (Phone Auth로 인증된 번호 자동 입력 가능)
        *   주소: 배달 선택 시 필수, 포장/현장결제 시 생략 가능
    *   **할인 적용**:
        *   포인트: `FEATURE_FLAGS.points`가 켜져 있으면 보유 포인트 조회 후 사용 가능 (최소 사용 한도 검증).
        *   쿠폰: 장바구니 단계에서 적용된 쿠폰 할인액이 반영됩니다.
    *   **결제 수단 선택**:
        *   `meet_card` (만나서 카드 결제)
        *   `meet_cash` (만나서 현금 결제)
        *   `app_card` (앱 결제 - NICEPAY)

### 1.3 결제 및 주문 완료 (Payment & Completion)
*   **결제 프로세스 (`handlePayment`)**:
    1.  **유효성 검사**: 약관 동의, 필수 정보(전화번호, 주소) 입력 여부 확인.
    2.  **주문 생성**: `createOrder` API 호출 -> Firestore `orders` 컬렉션에 문서 생성 (`status: pending`).
    3.  **결제 분기**:
        *   **현장 결제**: 즉시 주문 접수 처리 -> 성공 토스트 -> 주문 상세 페이지로 이동.
        *   **앱 결제 (NICEPAY)**:
            1.  `initiatePayment`: 서버로부터 인증 URL과 토큰 수신.
            2.  `openNicePayWindow`: 결제 팝업 오픈.
            3.  `pollPaymentResult`: 결제 결과 폴링 (성공/실패 대기).
            4.  성공 시 주문 상태 `paid` 업데이트 -> 완료 페이지 이동.
*   **사후 처리**:
    *   장바구니 비우기 (`clearCart`).
    *   포인트 사용 시 차감 처리 (`spendPoints`).

### 1.4 주문 조회 및 사후 활동 (Tracking & Review)
*   **주문 내역 (`OrderHistory.tsx`)**:
    *   Firestore `orders` 컬렉션에서 내 `uid`로 쿼리하여 리스트업.
    *   상태 뱃지 표시 (접수대기, 조리중, 배달중, 완료, 취소).
*   **실시간 추적 (`OrderTracking.tsx`)**:
    *   `onSnapshot` 리스너를 통해 주문 상태 변경(예: 조리중 -> 배달중)을 실시간으로 화면에 반영합니다.
*   **리뷰 작성 (`ReviewWrite.tsx`)**:
    *   '배달완료' 또는 '수령완료' 상태인 주문에 한해 리뷰 작성이 가능합니다.
    *   별점, 텍스트, 사진 업로드를 지원하며, 작성 시 포인트가 적립될 수 있습니다.

## 2. 👑 관리자(Admin) 시나리오 분석

점주님 또는 관리자가 주문을 접수하고 매장을 운영하는 흐름입니다.

### 2.1 진입 및 대시보드 (Dashboard)
*   **로그인**: `/admin` 경로 진입 시 `ProtectedRoute`가 권한(`owner` 또는 `admin`)을 체크합니다. 권한이 없으면 홈으로 튕겨나갑니다.
*   **대시보드 (`Dashboard.tsx`)**:
    *   **KPI 카드**: 오늘 매출, 오늘 주문 수, 평균 평점, PWA 설치율을 요약 표시합니다.
    *   **실시간 현황**: 새로운 주문이나 최근 리뷰가 들어오면 즉시 표시됩니다.
    *   **네비게이션**: 좌측 사이드바(모바일은 햄버거 메뉴)를 통해 주문, 메뉴, 통계 등으로 이동합니다.

### 2.2 주문 접수 및 관리 (Order Management)
*   **주문 목록 (`Orders.tsx`)**:
    *   **실시간 감지**: 5초 주기로 `fetchOrders`를 호출하거나 Firestore 리스너를 통해 새 주문을 감지합니다.
    *   **새 주문 알림**:
        *   상태가 `pending`인 새 주문이 들어오면 **"🔔 새 주문이 들어왔습니다!"** 다이얼로그가 팝업됩니다.
        *   **브라우저 오디오 API**를 통해 "띠링~" 알림음이 재생됩니다 (Web Audio API Oscillator 사용).
    *   **접수 처리**:
        *   알림 팝업에서 [접수하기] 클릭 -> 상태가 `accepted`로 변경됩니다.
        *   고객 앱에는 "주문이 접수되었습니다" 알림이 전송됩니다.
*   **상태 변경 흐름**:
    *   `pending` (대기) -> `accepted` (접수) -> `cooking` (조리중) -> `completed` (완료)
    *   배달 주문의 경우 `cooking` -> `delivering` (배달중) -> `completed` 단계가 추가됩니다.
*   **주문 취소**:
    *   [취소] 버튼 클릭 시 **취소 사유 입력 모달**이 뜹니다.
    *   사유 입력 후 확인 시 주문 상태가 `cancelled`로 변경되며, 앱 결제 건은 자동 환불 프로세스(서버 로직)가 트리거됩니다.

### 2.3 배달 관제 및 기타 (Delivery & Others)
*   **배달 관제 (`AdminDelivery.tsx`)**:
    *   배달 대행사(생각대로 등) 연동 상태를 확인하고 라이더 호출을 요청할 수 있습니다.
*   **메뉴 관리 (`Menus.tsx`)**:
    *   메뉴 품절 처리(Sold Out), 가격 수정, 숨김 처리를 즉시 반영할 수 있습니다.
*   **통계/분석 (`Analytics.tsx`)**:
    *   일간/주간/월간 매출 추이를 그래프로 확인합니다.

## 3. ⚠️ 주요 기술적 포인트 (놓치지 말아야 할 디테일)

1.  **Mock 모드와 Firebase 모드**:
    *   `config/env.ts`의 `USE_FIREBASE` 플래그에 따라 로직이 완전히 분기됩니다.
    *   현재 배포 버전은 **Firebase 모드**가 활성화되어 있으나, 결제는 Mock(테스트용)과 NICEPAY(실제)가 혼재되어 있습니다.
2.  **상태 동기화**:
    *   관리자가 주문 상태를 변경하면, 고객 앱의 `OrderTracking` 페이지에서 별도 새로고침 없이 상태가 변합니다 (Firestore 실시간 리스너).
3.  **결제 예외 처리**:
    *   `Checkout.tsx`에는 결제창 팝업이 차단되었을 때, 결제 승인 실패 시, 타임아웃 시에 대한 상세한 에러 핸들링(Toast 메시지)이 구현되어 있습니다.
4.  **관리자 알림음**:
    *   브라우저 정책상 사용자 인터랙션 없이 소리를 재생할 수 없으므로, 최초 클릭 이후부터 알림음이 정상 작동하도록 구현되어 있습니다.
