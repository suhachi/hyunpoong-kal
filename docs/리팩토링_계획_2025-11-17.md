1) 환경 스위치 일원화 (0.5h)

2) Auth Resolver 분리 (1.0h)
- 파일: `src/lib/auth/resolveUser.ts` (신규)
- 역할: Firebase userDoc → localStorage mockUser → 최소 사용자 객체, 3단계 폴백 공통화
- 적용: `src/contexts/AuthContext.tsx`에서 해당 유틸 사용하도록 정리

3) Fallback 유틸 생성 (1.0h)
- 파일: `src/lib/fallback.ts` (신규)
- 제공 함수: `getMockUser()`, `getOrdersFallback()`, `parseJSONSafe()`
- 적용: `src/pages/admin/Orders.tsx`의 로컬스토리지 파싱 로직 대체

4) E2E 유틸 디렉토리화 (0.5h)
- 디렉토리: `src/e2e/utils/`
- 항목: `auth.ts` → 익명 로그인 + users/{uid} 시드 + mockUser 동기화 헬퍼 공통화
- 적용: `order-flow.spec.ts` 등에서 공통 헬퍼 import 사용

## 변경 상세
- 환경 일원화
  - Export: `ENV`(그대로 외부 노출 유지), `USE_FIREBASE`, `FIREBASE_CONFIG`, 그리고 `export type AppEnv = 'development' | 'production' | 'test'`
  - Pass-1 원칙: "값의 의미"는 절대 변경하지 않고, 정의 위치만 `config/env.ts`로 통일
  - 운영 모드 전환(실제 동작 방식 변경)은 Phase 3 직전 별도 커밋로 분리해 롤백 용이성 확보

- Auth Resolver
  - `resolveUser(firebaseUser)` 반환: `AuthContext`의 `user` 타입과 1:1 동일하게 맞춤
  - 필수 필드 보장: `uid`, `role`, `storeId`, `displayName` 4개는 항상 존재하도록 강한 기본값 적용
  - 내부 단계: Firestore → localStorage(mockUser) → minimal default
  - 적용 순서(안전 이전):
    1) `AuthContext` 내부 헬퍼로 `resolveUserInternal` 도입
    2) E2E 및 수동 테스트로 정상 동작 확인
    3) `src/lib/auth/resolveUser.ts`로 이동(타입/동작 동일, 위치만 이동)
  - ProtectedRoute는 `user != null` 기준 유지

- Fallback 유틸
  - `getMockUser()` : localStorage 파싱 안전화(적용 범위: AuthContext, E2E 헬퍼)
  - `getOrdersFallback()` : 배열/객체 포맷 지원, 안전 파싱(적용 범위: AdminOrders)
  - `parseJSONSafe()` : 파싱 에러 시 `null` 반환(Pass-1에서는 Orders/mockUser에만 사용)
  - Pass-2에서 localStorage 전역 통합 정리 작업을 별도 진행(범위 확대는 보류)

- E2E 유틸
  - `loginAsAdmin(page, opts)` : 익명 로그인 + users/{uid} 시드 + mockUser 동기화
  - 경로: `src/e2e/utils/auth.ts` 유지, 파일 상단에 `// 테스트 전용 유틸` 주석 추가
  - 앱 코드(프로덕션/런타임)에서 해당 유틸을 import하지 않도록 규율 유지
  - 향후: 테스트 간 state cleanup 유틸 추가 고려
