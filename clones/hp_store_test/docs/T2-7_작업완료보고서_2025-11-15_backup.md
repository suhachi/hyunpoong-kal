# T2-7 작업완료보고서 — Admin Settings + 포인트 ON/OFF 뼈대 (2025-11-15)

## 개요
- 목적: 관리자 설정을 Mock 환경에서도 안전하게 저장/조회하고, 포인트 기능을 ON/OFF 할 수 있는 최소 뼈대를 구현.
- 범위: 타입 확장, 로컬 저장 분기(LocalStorage), 운영/보안 탭 토글 UI, 포인트 관리 페이지 게이트 처리.

## 주요 변경 사항
- 설정 타입 확장: `PointsSettings` 추가, `AdminSettings`에 `points` 포함 및 기본값 제공.
- Mock 안전 분기: `USE_FIREBASE=false` 시 `localStorage`에 관리자 설정 저장/조회.
  - 키: `hp_kal_admin_settings`
  - 날짜 직렬화: `updatedAt` ISO 문자열 저장/복원
  - 기본값의 `points.enabled`는 환경 토글 `FEATURE_FLAGS.points` 값을 반영
- UI: 운영/보안 탭에 "포인트 기능" 카드 + Switch 토글 추가
  - 토글 시 `saveAdminSettings()` 호출하여 지속 저장, 성공/실패 토스트 표시
- 관리자 포인트 페이지: 진입 시 관리자 설정을 읽어 `points.enabled`가 꺼져 있으면 안내 문구 렌더링

## 수정 파일 목록
- `src/types/adminSettings.ts`
  - `PointsSettings` 신규
  - `AdminSettings`에 `points` 필드 추가
  - `DEFAULT_POINTS_SETTINGS` 추가
- `src/lib/admin/settingsCenter.api.ts`
  - `USE_FIREBASE` 분기 도입 (Mock=LocalStorage / Real=Firestore)
  - `getAdminSettings`/`saveAdminSettings`에 로컬 저장 로직 및 안전 병합 추가
  - `points` 필드 기본값/병합 포함
- `src/pages/admin/Settings/OperationsTab.tsx`
  - 포인트 ON/OFF 스위치 카드 추가 (설정 로드/저장, 토스트 피드백)
- `src/pages/admin/Points.tsx`
  - `getAdminSettings()`로 `pointsEnabled` 확인 후 비활성 시 안내 렌더링

## 데이터 저장소/키
- LocalStorage 키: `hp_kal_admin_settings`
- 포함 필드: `delivery`, `maps`, `fcm`, `points`, `operations`, `updatedAt`, `updatedBy`, `updatedByName`

## 기능 토글 동작
- 전역 환경 토글: `FEATURE_FLAGS.points` (기본값: 개발 환경 true)
- 관리자 설정 토글: `AdminSettings.points.enabled`
  - 운영/보안 탭에서 ON/OFF 가능 (Mock 모드에서도 영속화)
  - 관리자 포인트 페이지는 두 토글 중 하나라도 false면 비활성 안내 표시

## 테스트 절차 (수동)
1) 빌드/프리뷰
   - 빌드: `pnpm exec vite build`
   - 미리보기: `pnpm exec vite preview --port 4173`
   - 접속: http://localhost:4173
2) 토글/저장 확인
   - 경로: 관리자 → 설정 센터 → 운영/보안
   - "포인트 기능" 스위치를 OFF 후, 새로고침 → OFF 유지 확인
   - `localStorage.getItem('hp_kal_admin_settings')`에서 `points.enabled` 값 확인
3) 관리자 포인트 페이지 게이트
   - 경로: 관리자 → 포인트 관리
   - OFF 상태에서 안내 메시지 표시 확인
   - 다시 ON 후 정상 목록/정책 카드 렌더링 확인

## 회귀 영향도
- 낮음: 타입 확장 및 설정 API 내 분기 추가이며, 기존 Firestore 경로는 유지.
- 주의: 클라이언트만으로 저장하는 Mock 모드 특성상 다른 기기와 설정 동기화는 되지 않음.

## 차기 과제(제안)
- Checkout 등 앱 내 포인트 UI/사용 로직도 `AdminSettings.points.enabled`와 동기화
- 포인트 정책(적립률/최소 사용/유효기간) 편집 UI 추가 및 저장
- 간단한 E2E: 운영 탭 토글 → 포인트 페이지 반응 검증
