### 2.2 왜 `menu`가 `undefined`인가?

#### 시나리오 A: 실제 앱 사용 (정상 작동)
```
사용자 동작: /menu 페이지에서 "현풍닭칼국수" 카드 클릭
→ 브라우저 이동: /menu/menu-001
→ useParams 추출: { menuId: "menu-001" }
→ 메뉴 데이터 검색: menusData.find(m => m.menuId === "menu-001")
→ 결과: ✅ menu 객체 찾음
```

#### 시나리오 B: E2E 테스트 (실패)
```
테스트 코드:
  await page.locator('a[href^="/menu/"]').first().click();
  
예상 동작:
→ 브라우저 이동: /menu/menu-001 (첫 번째 메뉴)
→ useParams 추출: { menuId: "menu-001" }
→ 메뉴 데이터 검색: menusData.find(m => m.menuId === "menu-001")
→ 결과: ✅ menu 객체 찾아야 함

실제 발생한 문제 (가설):
1. 메뉴 목록 렌더링 타이밍 문제
   - `a[href^="/menu/"]` 셀렉터가 메뉴 카드를 찾지 못함
   - 또는 잘못된 카드 클릭 (예: 로딩 스켈레톤)
   
2. 메뉴 데이터 로딩 실패
   - menusData가 빈 배열
   - 또는 JSON 파싱 오류
   
3. URL 파라미터 불일치
   - 클릭한 링크가 `/menu/undefined` 또는 `/menu/null`
   - useParams가 빈 문자열 반환
```

### 3.1 가설 1: 메뉴 목록 렌더링 타이밍 이슈 ⭐ (가능성 높음)

**원인**:
- 메뉴 목록 페이지가 완전히 렌더링되기 전에 `first()` 실행
- 로딩 중 플레이스홀더 카드가 먼저 매칭됨
- 플레이스홀더 링크: `<a href="/menu/undefined">` 또는 `<a href="/menu/">`

**증거**:
- `await expect(firstMenuCard).toBeVisible({ timeout: 10000 })` 통과
- → 카드는 보이지만 **올바른 카드가 아닐 수 있음**

**해결 방안**:

### 3.2 가설 2: MenuDetail에서 방어적 UI 렌더링 부족

**원인**:
- `menu`가 `undefined`일 때도 "담기" 버튼이 렌더링됨
- 버튼은 보이지만 클릭해도 아무 동작 안 함
- 토스트만 표시되어 사용자 혼란 유발

**증거**:
```tsx
const handleAddToCart = () => {
  if (!menu) return; // ⚠️ 조기 리턴하지만 토스트는 표시됨
  
  addItem({ ... });
  toast.success('장바구니에 담았습니다'); // 여기까지 도달 안 함
};
```

**해결 방안**:
```tsx
// ✅ 개선: menu가 없으면 "담기" 버튼 자체를 비활성화 또는 숨김
const handleAddToCart = () => {
  if (!menu) {
    toast.error('메뉴 정보를 불러올 수 없습니다');
    return;
  }
  
  addItem({ ... });
  toast.success('장바구니에 담았습니다');
};

return (
  <div>
    {!menu ? (
      <div>메뉴를 찾을 수 없습니다</div>
    ) : (
      <>
        {/* 메뉴 상세 UI */}
        <Button onClick={handleAddToCart} disabled={!menu}>
          담기
        </Button>
      </>
    )}
  </div>
);
```

### 3.3 가설 3: 라우터 파라미터 불일치 (낮은 가능성)

**결론**: 이미 수정되었으므로 이 가설은 제외

## 6. Playwright 모범 사례 위반 사항

### 6.1 불명확한 셀렉터 사용
```typescript
// ❌ Bad: 너무 광범위한 셀렉터
await page.locator('a[href^="/menu/"]').first().click();
// → /menu/undefined, /menu/loading 등도 매칭될 수 있음

// ✅ Good: 더 구체적인 패턴
await page.locator('a[href^="/menu/menu-"]').first().click();
// 또는
await page.locator('[data-testid="menu-card-menu-001"]').click();
```

### 6.2 중간 상태 검증 누락
```typescript
// ❌ Bad: 토스트만 확인하고 실제 상태는 검증 안 함
await addToCartButton.click();
await expect(page.getByText(/장바구니에 담았습니다/)).toBeVisible();

// ✅ Good: 실제 데이터 변경도 검증
await addToCartButton.click();
await expect(page.getByText(/장바구니에 담았습니다/)).toBeVisible();

const cartItems = await page.evaluate(() => {
  const data = localStorage.getItem('hyunpung_cart');
  return data ? JSON.parse(data).items : [];
});
expect(cartItems.length).toBeGreaterThan(0);
```

### 6.3 에러 발생 시 컨텍스트 부족
```typescript
// ❌ Bad: 실패 시 어떤 링크를 클릭했는지 알 수 없음
const firstMenuCard = page.locator('a[href^="/menu/"]').first();
await firstMenuCard.click();

// ✅ Good: 디버깅 정보 포함
const firstMenuCard = page.locator('a[href^="/menu/menu-"]').first();
const href = await firstMenuCard.getAttribute('href');
console.log('🔍 메뉴 링크:', href);

await firstMenuCard.click();

const currentUrl = page.url();
console.log('🔍 이동한 URL:', currentUrl);
```

## 7. 요약

### 7.1 문제 핵심
1. **표면적 증상**: `/cart` 페이지에서 `#pickup` 라디오 버튼이 없음
2. **실제 원인**: 장바구니가 비어있음 (아이템이 담기지 않음)
3. **근본 원인**: MenuDetail에서 `menu` 객체가 `undefined`
   - → `handleAddToCart()`가 조기 리턴
   - → `addItem()` 호출되지 않음
   - → 장바구니 비어있음
4. **왜 `menu`가 `undefined`?**: 
   - **가설 1** ⭐: E2E 테스트에서 잘못된 메뉴 카드 클릭 (로딩 중 플레이스홀더 등)
   - **가설 2**: MenuDetail 렌더링 시 데이터 로딩 실패
   - **가설 3**: URL 파라미터 불일치 (이미 수정됨)
