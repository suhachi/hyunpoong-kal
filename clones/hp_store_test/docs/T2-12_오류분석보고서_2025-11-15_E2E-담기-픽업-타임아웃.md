# T2-12 오류 분석 보고서 (2025-11-15)

## 개요
- 주제: E2E 테스트에서 장바구니 픽업 라디오(`#pickup`) 체크 단계 타임아웃 발생
- 영향 테스트:
  - `Order flow (Mock, payment OFF) › 고객이 메뉴를 주문하면 주문내역에서 보인다` (src/e2e/order-flow.spec.ts:98)
  - `Order flow (Mock, payment OFF) › 고객 주문이 관리자 주문 목록에도 표시된다` (src/e2e/order-flow.spec.ts:142)
- 증상: `locator('#pickup').check()` 30초 대기 후 타임아웃

## 재현 증상
- 테스트 스냅샷 기준 `/cart` 화면에 빈 카트 뷰 렌더링
  - "장바구니가 비어있어요", "메뉴 보러가기"만 보이고 배달/포장 라디오 그룹 미표시
  - 따라서 `#pickup` 요소가 존재하지 않아 체크 시 무한 대기

## 근본 원인 (Root Cause)
- 메뉴 상세 라우트 파라미터 불일치로 인해 메뉴 상세 진입이 항상 실패 → "담기" 버튼 미노출 → 카트가 비어 있는 상태로 `/cart` 진입
- 상세:
  - 라우터는 기존에 `menu/:id`를 사용한 곳이 있었고, 상세 페이지는 `useParams<{ menuId: string }>()`로 읽음
  - 파라미터 키가 달라 `menuId`가 `undefined` → `MenuDetail`이 "메뉴를 찾을 수 없습니다" 분기로 빠짐 → "담기" 불가

## 증거 (코드/스냅샷 인용)
- `MenuDetail` 파라미터 사용: `const { menuId } = useParams<{ menuId: string }>();`
- 빈카트 스냅샷: `heading "장바구니가 비어있어요"`, 버튼 "메뉴 보러가기"만 존재
- 카트 코드(`src/pages/app/Cart.tsx`)에서 빈 카트일 때 라디오 그룹 자체를 렌더하지 않음 → `#pickup`이 존재하지 않음

## 조치 사항
- 라우트 파라미터 명을 상세 컴포넌트와 일치하도록 정규화
- 적용된/확인된 라우트 정의:

```tsx
// src/App.tsx
<Route path="menu/:menuId" element={<MenuDetail />} />

// src/App.full.tsx (로컬 전체 라우팅 버전도 동일하게 유지)
<Route path="menu/:menuId" element={<MenuDetail />} />
```

- 이로써 `useParams`가 올바른 `menuId`를 수신 → 메뉴 상세 정상 렌더 → "담기" 버튼 노출 → 카트에 아이템 존재 → `/cart`에서 `#pickup` 라디오 렌더링/체크 가능

## Playwright 베스트 프랙티스 적용 권고
1. 상호작용 전 가시성 검증
   ```ts
   await expect(page.getByRole('button', { name: /담기/ })).toBeVisible();
   await page.getByRole('button', { name: /담기/ }).click();

   await page.goto('/cart');
   await expect(page.locator('#pickup')).toBeVisible();
   await page.locator('#pickup').check();
   ```
2. 데이터/라우팅 결정성 강화 (선택)
   - 첫 상품으로 이동 고정: `await page.goto('/menu/menu-001');`
   - 혹은 목록에서 첫 카드 대신 고정된 test id를 클릭
3. CI 환경 레이턴시 고려
   - `toBeVisible({ timeout: 10000 })` 등 여유 타임아웃 적용
4. 병렬성 이슈 회피 (초기 안정화 단계)
   - `--workers=1`로 직렬 실행 후 문제 소거 시 병렬 복귀

```powershell
pnpm exec playwright test -c src/playwright.config.ts --project=chromium --workers=1 -g "Order flow (Mock, payment OFF)"
```

## 리스크 및 회귀 방지
- 리스크: 다른 라우터 파일에서 파라미터명이 과거 형태로 남아있을 수 있음
  - 조치: `src/App.tsx`, `src/App.full.tsx`에서 동일 키(`menuId`) 유지 확인
- 회귀 방지: 메뉴 상세 진입 시나리오에 대한 라우팅 파라미터 스냅샷 테스트 추가 권장

## 결론
- 실패 원인은 라우트 파라미터 불일치로 인한 "담기" 미노출 → 카트 빈 상태 → `#pickup` 미존재 타임아웃
- 라우트 파라미터를 `:menuId`로 통일하여 해결
- 추가로, 테스트 내 가시성 검증과 결정성 강화를 적용하면 CI에서도 안정적으로 통과 가능
