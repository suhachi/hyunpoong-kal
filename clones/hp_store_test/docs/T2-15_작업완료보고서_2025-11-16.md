## T2-15 작업완료보고서 (2025-11-16)

### 1. 개요
- 프로젝트: 현풍닭칼국수 PWA (`hyunpoong-kal`)
- 브랜치: `feat/fix-first-20251113`
- 대상 기능: 장바구니(Cart) Hydration 및 E2E Order Flow 안정화 (Mock, payment OFF)
- 목적: `/cart` 페이지에서 `주문 방식` 섹션 미렌더링으로 인한 E2E 타임아웃(15초) 제거를 위해 CartContext/Cart.tsx 상태 동기화 구조 단순화.

### 2. 문제 정의
- 수동 브라우저 테스트: `itemsLength === 1`, `isHydrating: true → false` 정상 전환, 라디오(`#delivery`, `#pickup`) 표시됨.
- E2E (Playwright): `/cart` 진입 후 `장바구니` 텍스트까지만 노출되고 `주문 방식` 섹션 등장하지 않아 `getByText('주문 방식')` 대기가 15초 후 실패.
- 기존 구현 패턴:
  - CartContext: 초기 로드 + 다수 이벤트(storage/visibility/focus)에서 익명 `loadFromStorage` 반복 정의.
  - Cart.tsx: `forceReload()` 호출 후 이중 `setTimeout` 체인으로 `isHydrating` 종료. React 18 + 빠른 테스트 환경에서 타이밍/렌더 레이스 가능.

### 3. 가설 (Root Cause Hypothesis)
1. 다중 정의된 storage 동기화 로직이 빈번한 state set을 일으켜 Cart 초기 렌더 타이밍이 불안정.
2. Cart.tsx에서 이중 `setTimeout` 기반 hydration 종료는 테스트 속도/StrictMode 재마운트 조건에서 의도보다 늦거나 스피너 잔류 상태 유발.
3. Items가 이미 들어있는 상황에서도 불필요하게 `forceReload`를 추가 호출하며 렌더 순서를 교란.

### 4. 목표
`items`가 1회라도 반영되면 항상 Full UI(`주문 방식` 섹션 포함)가 즉시 렌더되도록 결정적(hard deterministic) 구조로 단순화.

### 5. 구현 내용 (Refactoring)
#### 5.1 CartContext (`src/contexts/CartContext.tsx`)
- 단일 `useCallback` 함수 `loadFromStorage` 도입: STORAGE_KEY 파싱 → 모든 관련 state(`items`, `deliveryType`, `deliveryAddress`, `requests`, `couponId`, `couponDiscount`) batch 업데이트.
- 초기 마운트 및 이벤트(storage / visibilitychange / focus) 바인딩을 하나의 `useEffect` 안에서 처리.
- JSON 파싱 오류는 try/catch로 안전 처리(콘솔만 출력).
- `forceReload`: 얇은(thin) wrapper → `loadFromStorage()`만 호출, 추가 부작용/지연 로직 제거.
- 중복/익명 로더 제거로 상태 재동기화 경로를 단일화.

#### 5.2 Cart 페이지 (`src/pages/app/Cart.tsx`)
- Hydration 상태 정의 단순화:
  - `isHydrating` 초기값 `true`.
  - 마운트 시 `items.length === 0`인 경우에만 1회 `forceReload` 호출.
  - `items.length` 변화를 감지하는 `useEffect`에서 즉시 `isHydrating = false` 전환 (다중 setTimeout 제거).
- 이미 items가 존재하면 강제 재로딩 생략 → 불필요한 state churn 제거.
- 디버깅 로그(T2-14) 유지: 추후 안정화 후 제거 예정.

### 6. 변경 전/후 비교 (핵심 흐름)
| 구분 | 이전 | 이후 |
|------|------|------|
| Storage 로드 | 익명 함수 여러 번 정의 | 단일 `loadFromStorage` |
| forceReload | 로직 중복 + setTimeout 후 검사 | 단순 호출 (wrapper) |
| Hydration 종료 | 이중 setTimeout 체인 | `items.length` 변화 즉시 종료 |
| 불필요 재로드 | items 있어도 호출 가능 | items 없을 때만 1회 호출 |
| 타임아웃 위험 | 스피너 잔류 가능성 | 결정적 렌더 경로 확보 |

### 7. 기대 효과
- `/cart` 진입 후 items가 있으면 항상 빠르게 `주문 방식` 섹션 노출 → E2E `getByText('주문 방식')` 15초 타임아웃 제거.
- 상태 동기화 경로 단일화로 디버깅 용이성 및 재현성 향상.
- React 18 StrictMode 재마운트에도 안전한 초기화 시퀀스.
