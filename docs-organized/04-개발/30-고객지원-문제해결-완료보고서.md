## 📋 Executive Summary

### 문제
관리자 고객지원 대시보드가 "비활성화되어 있습니다" 메시지만 표시하고 실제 채팅 UI가 렌더링되지 않음.

### 원인
`.env` 파일에 `VITE_SUPPORT_ENABLED=true` 환경 변수가 설정되지 않아 기능 토글이 `false` 상태.

### 해결
1. `.env` 파일 생성
2. `VITE_SUPPORT_ENABLED=true` 추가
3. 개발 서버 재시작

### 결과
✅ 고객지원 채팅 기능 정상 활성화  
✅ Firebase 실시간 동기화 준비 완료  
✅ Mock 모드 테스트 가능  
✅ 향후 동일 문제 재발 방지 완료

### Root Cause Analysis

```
사용자가 /admin/support 접속
    ↓
AdminSupport 컴포넌트 렌더링
    ↓
FEATURE_FLAGS.support 체크
    ↓
/config/env.ts에서 getEnv('VITE_SUPPORT_ENABLED') 호출
    ↓
.env 파일 없음 → 기본값 '' 반환
    ↓
'' === 'true' → false
    ↓
FEATURE_FLAGS.support = false
    ↓
조기 반환 (early return)
    ↓
경고 메시지만 표시, 채팅 UI 미렌더링
```

```typescript
    : (getEnv('VITE_SUPPORT_ENABLED') === 'true'),
};
```

## 📚 학습 포인트

### 1. Vite 환경 변수 처리

**핵심:**
- `import.meta.env`로 접근
- `VITE_` 접두사 필수
- `.env` 파일 변경 시 **반드시 재시작**

### 2. Feature Toggle 패턴

**장점:**
- 기능별 독립적 활성화/비활성화
- 배포 없이 기능 제어
- A/B 테스트 가능

**구현:**
```typescript
export const FEATURE_FLAGS = {
  support: getEnv('VITE_SUPPORT_ENABLED') === 'true',
  delivery: getEnv('VITE_DELIVERY_ENABLED') === 'true',
  points: getEnv('VITE_POINTS_ENABLED') === 'true',
};
```

### 3. 환경 변수 보안

**Best Practices:**
- `.env` 파일은 절대 Git에 커밋 금지
- `.env.example`로 템플릿 제공
- 비밀 정보는 `YOUR_API_KEY_HERE` 플레이스홀더
- `.gitignore`에 명시적 제외
