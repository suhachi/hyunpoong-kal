## 📋 Issue #4: 환경 변수 검증 개선

### 문제
```typescript
// config/env.ts - 수정 전
const getEnv = (key: string, defaultValue: string = ''): string => {
  try {
    return import.meta?.env?.[key] || defaultValue;
  } catch {
    return defaultValue;
  }
};

// 문제점:
// - 필수 변수 검증 없음
// - 오류 로깅 부족
// - ENV 순환 참조
```

### 해결
```typescript
// config/env.ts - 수정 후

// 1. ENV, DEBUG 먼저 정의 (순환 참조 방지)
export const ENV = (() => {
  try {
    return import.meta?.env?.MODE || 'development';
  } catch {
    return 'development';
  }
})();

export const DEBUG = ENV === 'development';

// 2. 강화된 getEnv 함수
const getEnv = (
  key: string, 
  defaultValue: string = '', 
  required: boolean = false  // ✅ 필수 변수 플래그
): string => {
  try {
    // import.meta.env 확인
    if (typeof import.meta === 'undefined' || !import.meta.env) {
      if (required) {
        console.error(`[Env] Required variable ${key} not available`);
      } else if (DEBUG) {
        console.warn(`[Env] Using default for ${key}`);
      }
      return defaultValue;
    }
    
    const value = import.meta.env[key];
    
    // 필수 변수 검증
    if (!value && required) {
      console.error(`[Env] Required variable ${key} is not set`);
      if (ENV === 'production') {
        throw new Error(`Required environment variable ${key} is not set`);
      }
    }
    
    // 경고 로깅
    if (!value && !defaultValue && DEBUG) {
      console.warn(`[Env] ${key} has no value and no default`);
    }
    
    return value || defaultValue;
  } catch (error) {
    console.error(`[Env] Error accessing ${key}:`, error);
    return defaultValue;
  }
};
```

### 개선 사항
- ✅ **필수 변수 검증** - `required` 플래그
- ✅ **상세한 로깅** - 개발/프로덕션 분리
- ✅ **순환 참조 해결** - ENV, DEBUG 먼저 정의
- ✅ **프로덕션 에러** - 필수 변수 없으면 throw
- ✅ **개발 경고** - 디버그 모드에서 경고

### 변경 파일
- ✅ `/config/env.ts` - 함수 강화 및 순환 참조 해결

## 📋 Issue #5: Timestamp 타입 의존성

### 문제
```typescript
// types/order.ts - 수정 전
import type { Timestamp } from 'firebase/firestore';  // ❌ Firebase 강제 의존

export interface Order {
  // ...
  createdAt: Timestamp;   // Firebase 타입
  updatedAt: Timestamp;   // Firebase 타입
}
```

### 문제점
- Firebase 패키지 없으면 타입 오류
- Mock 모드에서 타입 불일치
- Firebase 의존성 강제

### 해결
```typescript
// types/order.ts - 수정 후

// Firebase Timestamp 타입 (선택적)
// Firebase 사용 시: Timestamp from firebase/firestore
// Mock 모드 시: { seconds: number; nanoseconds: number }
type FirebaseTimestamp = {
  seconds: number;
  nanoseconds: number;
  toDate?: () => Date;  // 선택적 메서드
};

export interface Order {
  // ...
  createdAt: FirebaseTimestamp;  // ✅ 독립적 타입
  updatedAt: FirebaseTimestamp;  // ✅ 독립적 타입
}
```

### 개선 사항
- ✅ **Firebase 독립** - firebase/firestore import 제거
- ✅ **Mock 호환** - Mock 데이터와 타입 일치
- ✅ **유연성** - Firebase/Mock 모두 지원
- ✅ **타입 안전성** - seconds, nanoseconds 보장

### 변경 파일
- ✅ `/types/order.ts` - 타입 정의 수정
