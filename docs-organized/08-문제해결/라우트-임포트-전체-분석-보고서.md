- Named export: 6개 (40%)
- Default export: 9개 (60%)

- Named export: 1개 (9%)


이는 개발자가 새 페이지 추가 시 어떤 방식을 사용해야 할지 혼란을 야기함.

## 4. 문제점 및 위험도

### 4.1 심각도: 🟡 중간

현재 코드는 **정상 작동**하지만, 유지보수성에 문제가 있음.

### 4.2 구체적 문제점

#### ❌ 문제 1: 일관성 부재
**영향**: 코드베이스 전반의 일관성 저하

```typescript
// 🔴 현재 (불일치)
import { Home } from "./pages/app/Home";
import OrderHistory from "./pages/app/OrderHistory";

// ✅ 권장 (일관)
import { Home } from "./pages/app/Home";
import { OrderHistory } from "./pages/app/OrderHistory";
```

#### ❌ 문제 2: 리팩토링 어려움
**영향**: 컴포넌트 이름 변경 시 혼란

```typescript
// Default export 사용 시
import Foo from "./pages/app/OrderHistory"; // 가능하지만 혼란스러움
```

#### ❌ 문제 3: 자동 완성 저하
**영향**: IDE의 자동 완성 기능이 덜 효과적

Named export를 사용하면 IDE가 정확한 컴포넌트 이름을 자동 완성할 수 있음.

#### ❌ 문제 4: Tree Shaking 비효율
**영향**: 번들 크기 증가 가능성

Named export가 더 효과적인 Tree Shaking을 제공함 (단, 이 프로젝트에서는 영향 미미).
